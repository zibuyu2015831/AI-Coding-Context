# AICC Plugin Build — Execution Spec

> **Audience**: the Claude Code `/goal` session that builds the plugin in one run.
> **This file is the blueprint.** Rationale lives in `README.md` / `01` / `02`; do not re-derive it — execute this.
> **Everything you generate is English.** The planning docs may be Chinese; your output (every file under `plugin/`, every description, comment, message, README) MUST be English (decision D5).

---

## 0. Invariants (never violate)

1. **Branch**: work ONLY on `plugin` (already derived from `dev`). Never commit to `dev` or `master`.
2. **Baseline = `dev`**: the source of truth for AICC capabilities is the `dev` branch working tree (NOT master — dev is ahead and unmerged). **Mandatory first action, before P0**: `git merge dev` into `plugin`. If it conflicts, ABORT and report — a semantic merge is the user's call, not the goal's.
3. **Goal = the COMPLETE plugin, in one run if budget allows** (§0.5): build all of P0→P5 (every skill, hook, agent, bin, settings, build tooling, Codex projection, docs) to the §10 final gate. Do not stop at a partial slice while session budget remains.
4. **Resumable (safety net, not a cap)**: progress is journaled by checkpoint commits. On every run, FIRST detect what already exists under `plugin/` and continue from the first unmet checkpoint. A budget-limited session therefore loses no work and re-running converges to full completion — never restart.
5. **English-only output** (D5): all plugin artifacts in English. No Chinese (no CJK) in shipped files.
6. **Convergence is the entry ticket** (D3): never copy an asset 1:1. Apply its convergence action (§6) BEFORE it enters `plugin/`. If an asset cannot be converged within budget, leave it out and log it in `plugin/BUILD_NOTES.md`.
7. **Do not touch the clone form**: `master`/`dev` clone usage must keep working. You ADD `plugin/`; you do not delete `core/`, `workflows/`, `agents/`, `tools/`, `templates/`, `guides/` from the source tree. `build.py` asserts these exist before and after; abort if any shrank.
8. **Single source, build-time copy** (skill-migration #10/#11): `plugin/` is generated by copying + converging from `core/workflows/templates/agents/tools`; never symlink. Record provenance in `plugin/build/manifest.generated.json`.
9. **Real assets only**: map only files that actually exist on `dev`. Before mapping any role/tool/template, confirm it exists. Log phantom references instead of inventing files.
10. **Checkpoint commits**: one commit per phase P0→P5 (§9), each with its acceptance self-check result in the commit body.

---

## 0.5 Build order & resumability (drive to FULL completion)

The target is the **complete** plugin (all of §9, to the §10 gate) in this run. The phase order below is the build sequence — follow it start to finish; do not stop early while session budget remains.

**Order of construction (each phase = a checkpoint commit):**
1. **Core slice first (P0 → P1.5)** — the irreplaceable value, built and verified before breadth:
   - P0 skeleton (plugin.json, hooks.json, build.py + lint, manifest) + P0 hook smoke-test (§4).
   - `session_inject.py` (zero-paste) + `pre_commit_gate.py` + `dangerous_git_guard.py` — the enforcement layer (#1 reviewed gap).
   - skills `init`, `health-check`, `incremental-update`; shared `references/framework-boundary.md`; `settings.json`.
   - dev-time agents `architecture-analyst`, `product-manager`; bin `aicc-doc-health`, `aicc-scan`, `aicc-summary-validate`.
2. **Breadth (P2 → P3)** — `design-thinking`, `mutual-review`, `adr`, then `doc-fallacy-fix`, `systematic-review`, `doc-reading-habit`, `knowledge-reuse`, `complexity-dashboard` (only if it passes the §6 ship gate), remaining agents + bin.
3. **Finishing (P3.5 → P5)** — `post_tool_audit` telemetry, Codex projection (§7), `plugin/README.md`, clone→plugin migration guide, `BUILD_NOTES.md`, final §10 gate.

**Resumability (safety net so one run = full task even if budget-limited):** before building, scan `plugin/` and resume at the first unmet checkpoint; never redo a completed, committed phase. If the session is about to exhaust its budget, finish the current phase, make its checkpoint commit, and end with a one-line "resume at P<n>" note — re-pasting the kickoff continues to completion with zero rework. **Do not voluntarily stop short of P5 while budget remains.**

> Rationale: ordering the enforcement + 3 core skills first guarantees the highest-value capability is whole even in the worst case; resumability guarantees the *entire* conversion completes regardless of any single session's budget. This satisfies "finish the whole conversion in one go" while staying robust to context limits (the readiness review's scope-realism finding).

## 4. Hooks — the enforcement layer (the core value-add)

`hooks/hooks.json`:

```jsonc
{
  "hooks": {
    "SessionStart": [
      { "hooks": [{ "type": "command",
        "command": "python3 \"${CLAUDE_PLUGIN_ROOT}/hooks/session_inject.py\"",
        "description": "AICC: inject framework model + project doc-health snapshot" }] }
    ],
    "PreToolUse": [
      { "matcher": "Bash", "if": "Bash(git commit*)",
        "hooks": [{ "type": "command",
          "command": "python3 \"${CLAUDE_PLUGIN_ROOT}/hooks/pre_commit_gate.py\"",
          "description": "AICC: doc-health + contract gate before commit" }] },
      { "matcher": "Bash", "if": "Bash(git (push --force*|push -f*|reset --hard*|clean -f*))",
        "hooks": [{ "type": "command",
          "command": "python3 \"${CLAUDE_PLUGIN_ROOT}/hooks/dangerous_git_guard.py\"",
          "description": "AICC: block destructive git operations" }] }
    ],
    "PostToolUse": [
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "async": true,
          "command": "python3 \"${CLAUDE_PLUGIN_ROOT}/hooks/post_tool_audit.py\"",
          "description": "AICC: append minimal telemetry to ${CLAUDE_PLUGIN_DATA}" }] }
    ]
  }
}
```

Hook script contracts (stdin = event JSON; all messages English):

| script | event | behavior | output contract |
| --- | --- | --- | --- |
| `pre_commit_gate.py` | PreToolUse(git commit) | run `summary_validator` + `framework_contract_checker` on changed `*.md`; on failure return deny | `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny"|"allow","permissionDecisionReason":"…"}}`. **Ship default `ask` (warn + confirm); flip to `deny` via settings once stable** (§5, risk mitigation) |
| `dangerous_git_guard.py` | PreToolUse(force/reset/clean) | deny unless `git_safety.mode=permissive` in settings | same contract; `deny` + reason |
| `session_inject.py` | SessionStart | print skill catalog + `dev_docs/` presence + health snapshot (reuse `doc_health_checker`) | stdout `additionalContext` string; never block |
| `post_tool_audit.py` | PostToolUse | append `{ts,tool,skill?,docs_changed}` JSONL to `${CLAUDE_PLUGIN_DATA}/telemetry.jsonl` | exit 0; async; never block |

**Concrete I/O examples** (English messages):

```json
// pre_commit_gate.py — on failure
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny",
 "permissionDecisionReason":"AICC gate: summary_validator found 3 docs with missing frontmatter (api_layer.md, auth.md, db.md). Fix or run with git_safety.commit_gate=ask."}}

// session_inject.py — SessionStart
{"hookSpecificOutput":{"hookEventName":"SessionStart",
 "additionalContext":"AICC skills available: /aicc:init (no docs yet), /aicc:health-check, /aicc:incremental-update.\nProject: dev_docs/ present; 6 docs, 1 stale (>90d). Run /aicc:health-check to assess."}}
```

**Robustness contract** (all hooks): non-zero exit / malformed JSON ⇒ PreToolUse defaults to `deny` with the error as reason; SessionStart & PostToolUse default to no-op (never break the session). Missing tool on PATH ⇒ log a warning and `allow`/no-op (fail-open for non-Git hooks, fail-safe `ask` for the commit gate).

**Schema verification (do this in P0, do not assume)**: the exact `if`-matcher semantics and hook output schema vary by Claude Code version. Before relying on the patterns above, build the P0 skeleton with ONE real `deny` hook and smoke-test that (a) the matcher fires on `git commit`, (b) the `deny` JSON is honored. Adjust shapes to the installed version if they differ; record the confirmed schema in `plugin/BUILD_NOTES.md`. If the `(a|b|c)` alternation in the dangerous-git matcher does not fire, split it into separate entries (`git push --force`, `git reset --hard`, …).

> This is the only mechanism that turns AICC's "advisory" flows into enforceable ones — the #1 gap both reviews named. `session_inject.py` eliminates the manual "paste AI_ENTRY_POINT.md" friction.

## 5. Config → settings (make config actually drive behavior)

Convert `config/CONFIG_TEMPLATE.md` keys into three destinations (fixes review P1 "config wired thinly"):

| key(s) | destination | effect |
| --- | --- | --- |
| `documentLanguage`, `enableMutualReview`, `enforceDesignThinking`, `aiCapabilityTier` | `plugin/settings.json` defaults (user overrides in `.claude/settings.json`) | natively read by Claude Code; referenced by skill bodies |
| `git_safety.mode`, `protected_branches`, `require_branch_naming` | read by `hooks/*` at runtime | enforced (deny), not advisory |
| project-specific config docs | stays as user-project `dev_docs/configuration.md` | unchanged |

`settings.json` seed:

```json
{
  "aicc": {
    "documentLanguage": "en",
    "enableMutualReview": true,
    "enforceDesignThinking": false,
    "git_safety": { "mode": "standard", "commit_gate": "ask", "protected_branches": ["main","master","production"] }
  }
}
```

Any key kept in `settings.json` MUST be read somewhere (a skill body or a hook). Drop keys nothing consumes; list dropped keys in `BUILD_NOTES.md`.

## 6. Convergence targets (apply BEFORE migrating; verify line budgets)

| asset | action | hard target |
| --- | --- | --- |
| `AI_ENTRY_POINT.md` (811L) | routing → skill `description`s; boundary rules → `references/framework-boundary.md` | boundary ref ≤ 40L; entry doc NOT shipped in plugin |
| `path_a` (1049L) etc. | skeleton in body, details in references | each skill body ≤ its §3 budget |
| 6× `generation_plan_*` templates | one parametric template + conditional fragments | 1 file, ≤ 600L total (was ~ 2万行 across 6) |
| 2× progress templates | merge to one | 1 file |
| 2× commit-guided guides | merge to one | 1 file |
| ~20 role files (≈50% boilerplate) | extract shared template; convert to English; only ship coupled-runtime + 4 dev-time | boilerplate removed |
| personas (Linus/Fowler/Uncle Bob) | fold into `design-thinking`/`mutual-review` `perspective` param | 0 standalone files |
| quantified claims (99/80/90/29/50…) | delete or make qualitative when copying any text | 0 unsubstantiated numbers in plugin |
| complexity dashboard | make metrics real + scale-calibrate thresholds, else OMIT | ship only if real |

**Global budget check** (target, not abort-trigger): total **doc** lines under `plugin/` — i.e. `skills/ + references/ + agents/`, **excluding `scripts/` and `build/`** — should be ≤ 50% of the current public doc corpus (baseline ≈ 63,176 lines). Record the measured number in `BUILD_NOTES.md`; if over, converge further or log why not.

**`converged: true` definition** (for the manifest): a mapped file counts as converged iff ONE holds — (a) the source is dropped entirely (e.g., personas not shipped), (b) ≥30% net line reduction after stripping boilerplate, or (c) it is a merge of ≥2 sources into one. Otherwise `converged: false` + reason in `BUILD_NOTES.md`.

**`AI_ENTRY_POINT.md` (811L) explicit mapping**: framework overview / pain-points / config guide → **delete** (not shipped); routing/decision-tree → embedded into each skill's `description`; project-exclusion rules → `references/framework-boundary.md` (≤40L); quick-start snippet → `plugin/README.md`. Net: ~5L reference + ~20L README; the rest is deleted, not moved.

**`complexity-dashboard` ship gate** (resolve by auditing `dev/complexity/` at build time): SHIP the skill ONLY IF (1) `dev/complexity/data/` holds real metrics (not just a mock `test.json`), AND (2) thresholds in `config.yaml` are scale-calibrated for small/medium/large projects. Otherwise OMIT the skill and log `"complexity-dashboard deferred: scaffolding only"` in `BUILD_NOTES.md`. (As of this writing the data dir holds only an 837-byte mock → default OMIT unless made real first.)

## 7. Codex flat-package projection (secondary, after all Claude Code work)

`build/build.py` also emits `dist/codex/` from the SAME skill sources:
- rename skill dirs to `aicc-<name>` (no plugin namespace on Codex);
- replace hook-enforced steps with an in-body "Recommended: run `aicc-doc-health` before commit" note (advisory — Codex has no hooks);
- emit an `AGENTS.md` index pointing at the flat skills.
No separate content authoring; Codex output is a pure projection. Do NOT target any other platform.

---

## 8. Build tooling

`build/build.py`:
1. read source from `dev` tree (core/workflows/templates/agents/tools);
2. apply convergence (§6), write English artifacts into `plugin/`;
3. write `manifest.generated.json` (each plugin file → source(s), converged: true/false, line counts);
4. project Codex flat package (§7);
5. assert all budgets (§3, §6) and English-only (no CJK chars in shipped files); fail loudly otherwise.

CI lint (a `bin/aicc-lint` or `build/lint.py`): description style (≤1024, "Use when"), body line budgets, reference depth ==1, no CJK in `plugin/`, every `settings.json` key referenced somewhere. This lint is the standing reverse-entropy guard.

## 9. Build order + checkpoint commits (one-shot, sequential)

| # | checkpoint | deliverable | acceptance self-check (put result in commit body) |
| --- | --- | --- | --- |
| P0 | skeleton | plugin.json, empty skills, hooks.json with one real `deny` hook, build.py stub, lint | `--plugin-dir plugin` loads; pre_commit_gate denies a deliberately-broken commit |
| P1 | core skills + injection | `init` + `health-check` skills + `session_inject.py` | zero-paste: a fresh session auto-knows AICC + project health; both skills trigger on intent |
| P1.5 | enforcement | `incremental-update` + `pre_commit_gate` + `dangerous_git_guard` (live) | gate blocks a non-compliant commit; force-push blocked unless permissive |
| P2 | thinking skills | `design-thinking` + `mutual-review` + `adr` | chained skill trigger works; personas are params not files |
| P3 | remaining | `doc-fallacy-fix`, `systematic-review`, `doc-reading-habit`, `knowledge-reuse`, (`complexity-dashboard` only if real) | global line budget ≤50% verified & recorded |
| P3.5 | telemetry | `post_tool_audit.py` | telemetry.jsonl populated; at least one old quantified claim replaced/withdrawn |
| P4 | Codex projection | `dist/codex/` | flat package builds from same source; advisory degradation noted |
| P5 | migration + docs | `plugin/README.md`, clone→plugin migration guide, BUILD_NOTES.md | README install works; manifest complete |

**Trigger-accuracy check (how to measure "skill triggers on intent")**: for each shipped skill, hand-test 3 positive prompts and 2 negative prompts and confirm Claude selects the right `/aicc:*` skill (and NOT a sibling). Example for `init`: positives "set up AI docs", "generate the AI coding context", "initialize AICC for this repo"; negatives "update the docs after my change" (→ incremental-update), "review this plan" (→ mutual-review). Pass = all 5 correct. Record pass/fail per skill in the checkpoint commit body.

## 10. Final acceptance gate (the conversion is DONE when all pass)

> A single run drives toward all of these; if budget-limited, resumed runs converge here. The task is complete only when every box is checked.

- [ ] `pre_commit_gate` returns `deny` on a broken-frontmatter commit (set `commit_gate:"deny"` to test), `allow` otherwise.
- [ ] `session_inject` injects catalog + health snapshot with no user paste.
- [ ] Every shipped file is English (lint: no CJK under `plugin/`).
- [ ] Total `plugin/` doc lines (excl. scripts) ≤ 50% of 63,176; number recorded in BUILD_NOTES.md.
- [ ] `manifest.generated.json` covers every shipped file with provenance.
- [ ] No unsubstantiated quantified claim anywhere in `plugin/`.
- [ ] `master`/`dev` clone form still intact (no source dirs deleted).
- [ ] Codex flat package builds from the same sources.
- [ ] All P0–P5 checkpoint commits present on branch `plugin`.
