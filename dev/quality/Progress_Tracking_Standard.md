# 审查进度跟踪标准

本文档定义了AI Coding Context框架审查过程中进度跟踪的标准与规范，确保审查活动可以在中断后准确恢复。

## 📋 进度跟踪要素

### 进度表结构
每个审查的进度跟踪表应包含以下要素：
1. **审查标识**：审查目录名称和唯一标识
2. **总体进度**：整体完成百分比
3. **阶段进度**：各审查阶段的完成状态
4. **任务清单**：具体任务的完成状态
5. **中断点**：如果中断，记录中断位置和上下文
6. **下次行动**：恢复审查时的下一步行动
7. **问题统计**：已发现问题的数量和类型
8. **时间记录**：各阶段和任务的时间消耗

## 🔄 进度更新流程

### 定期更新
1. **每完成一个任务**：立即更新任务清单状态
2. **每切换一个阶段**：更新阶段进度和总体进度
3. **每发现一个问题**：更新问题统计
4. **每小时**：更新时间记录
5. **中断时**：立即记录中断点和恢复指令

### 恢复审查流程
1. **读取进度表**：获取中断位置和上下文
2. **恢复环境**：根据工具状态恢复审查环境
3. **确认状态**：验证中断时的发现是否仍然有效
4. **继续执行**：根据恢复指令继续审查活动

## ⚠️ 中断处理最佳实践

### 中断前
1. 完成当前任务或记录到可中断点
2. 保存所有打开的文档和工具状态
3. 更新进度表，详细记录中断点
4. 保存问题跟踪表的最新状态

### 恢复后
1. 仔细阅读进度表，理解中断上下文
2. 验证之前发现的问题是否仍然存在
3. 检查是否有新的变更影响审查范围
4. 从中断点继续，避免重复工作
