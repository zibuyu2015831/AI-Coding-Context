# 批量生成审查上下文指南

> **用途**: 指导如何批量生成框架文档的审查上下文  
> **适用场景**: V3.0 完成后的全面审查准备、新文档加入框架时  
> **预估工作量**: 4-6 小时（30+个文档）  
> **版本**: v1.0

---

## 📋 任务概述

### 需要生成的上下文数量

**总计**: 30+个文档的审查上下文

**分类统计**:

- 入口文档: 2 个
- 核心规范文档 (core/): 4 个
- 工作流文档 (workflows/): 7 个
- 指导文档 (guides/): 6 个
- 模板文档 (templates/): 10+个

### 生成原则

1. **基于模板** - 使用 `contexts/_template.md` 作为基础
2. **信息准确** - 从实际文档中提取信息，不臆测
3. **格式统一** - 所有上下文遵循相同的结构
4. **质量保证** - 每个上下文都要验证完整性

---

## 🤖 AI 使用指南

### 两种使用场景

**场景 A: 批量生成（V3.0 完成后）**

- 一次性生成 30+个文档的审查上下文
- 适合框架重大版本发布后
- 工作量大，建议分批执行

**场景 B: 单个新文档（日常使用）** ⭐

- 框架新增单个文档时
- 快速生成该文档的审查上下文
- AI 可以自动化执行

### AI 执行模式

当用户请求"为 XX 文档生成审查上下文"时：

```
【AI执行步骤】
1. 跳转到 "单个新文档上下文生成工作流" 章节
2. 按照该工作流的步骤执行
3. 生成上下文文件
4. 验证质量
5. 保存并报告
```

## 🆕 单个新文档上下文生成工作流

> **适用场景**: 框架新增单个文档，需要为其生成审查上下文  
> **可 AI 执行**: ✅ 是  
> **预估时长**: 5-10 分钟

### 步骤 1: 确认新文档信息

**AI 需要获取的信息**:

- [ ] 新文档的完整路径（相对于项目根目录）
- [ ] 新文档所属类型（入口/核心/工作流/指导/模板）
- [ ] 新文档的实际内容

**如何获取**:

```python
# 伪代码示例
new_doc_path = "workflows/new_feature_workflow.md"  # 用户提供或AI检测
doc_type = "工作流"  # 根据路径或内容判断
doc_content = read_file(new_doc_path)  # 读取文档内容
```

### 步骤 2: 确定上下文文件名

**命名规则**:

```
入口文档: AI_ENTRY_POINT.md, README.md
核心规范: core_{filename}.md
工作流: workflows_{filename}.md
指导文档: guides_{filename}.md
模板: templates_{filename}.md
```

**示例**:

- `workflows/new_feature_workflow.md` → `workflows_new_feature_workflow.md`
- `core/new_rule.md` → `core_new_rule.md`

### 步骤 3: 读取上下文模板

```markdown
【AI 执行】
读取文件: quality/contexts/\_template.md
获取完整模板内容
```

### 步骤 4: 分析新文档并提取信息

**AI 需要提取的关键信息**:

1. **文档定位**

   - 文件路径（已知）
   - 目标受众（从文档内容判断：AI/人类/两者）
   - 在框架中的角色（一句话概括）

2. **核心职责**（3-5 条）

   - 从文档的主要章节提取
   - 用"动词+对象"格式表述

3. **必须包含的内容**

   - 列出文档的主要章节
   - 每个章节的关键要点

4. **关联文档**

   - 分析文档中的链接
   - 推断逻辑上的关联关系
   - 上游文档（谁引用这个文档）
   - 下游文档（这个文档引用谁）
   - 同类文档（相同类型的其他文档）

5. **特定检查要点**

   - 基于文档类型和内容特点
   - 至少 3-5 个具体检查项

6. **优化重点**
   - 识别文档中最关键的部分
   - 提示审查者重点关注

### 步骤 5: 填充模板生成上下文

**AI 执行**:

```markdown
【基于模板和提取的信息生成完整的上下文文档】

## 示例输出结构：

# [新文档名] - 审查上下文

> **使用方式**: [标准说明]

## 📋 文档定位

[填充提取的信息]

## 🎯 核心职责

[3-5 条职责]

## 📄 必须包含的内容

[章节和要点]

## 🔗 关联文档

[上游/下游/同类文档]

## ✅ 特定检查要点

[具体检查项]

## 🎯 优化重点

[重点说明]

## 📝 审查记录

## [初始状态]
```

### 步骤 6: 质量自检

**AI 自我验证清单**:

- [ ] 文件路径准确
- [ ] 核心职责数量合理（3-5 条）
- [ ] 至少有 3 个特定检查要点
- [ ] 关联文档部分不为空（至少有下游或同类）
- [ ] 所有占位符已填充
- [ ] Markdown 格式正确
- [ ] 链接格式符合规范
- [ ] 日期为当前日期

**如果检查未通过**: 重新分析并修正

### 步骤 7: 保存文件

**保存路径**: `quality/contexts/[上下文文件名].md`

**AI 执行**:

```python
# 伪代码
context_filename = generate_context_filename(new_doc_path)
save_path = f"quality/contexts/{context_filename}"
save_file(save_path, generated_context)
```

### 步骤 8: 更新索引（可选）

**如果需要**: 更新 `quality/README.md` 中的文档索引，添加新文档的条目

**示例**:

```markdown
### 工作流文档 (workflows/)

... (已有文档)

- [ ] [new_workflow.md](../../workflows/new_workflow.md) → [审查上下文](./contexts/workflows_new_feature_workflow.md)
```

### 步骤 9: 报告完成

**AI 应该向用户报告**:

```markdown
✅ 已完成为 [新文档名] 生成审查上下文

**生成的文件**: quality/contexts/[上下文文件名].md

**关键信息**:

- 文档类型: [类型]
- 核心职责: [数量]条
- 检查要点: [数量]个
- 关联文档: [数量]个

**质量自检**: ✅ 已通过

**后续建议**:

1. 请人工审核生成的上下文
2. 如有需要，手动调整
3. 更新 quality/README.md 索引（如需要）
```

## 🔄 批量生成工作流

### 准备阶段

**步骤 1: 准备工作清单**

创建一个清单文件（可以是 Excel 或 Markdown）：

```markdown

| 1    | 入口     | AI_ENTRY_POINT.md      | AI_ENTRY_POINT.md      | ⚪ 待生成 |
| 2    | 入口     | README.md        | README.md        | ⚪ 待生成 |
| 3    | 核心     | core/language_rules.md | core_language_rules.md | ⚪ 待生成 |
| ...  | ...      | ...                    | ...                    | ...       |
```

**步骤 2: 准备参考材料**

- ✅ `quality/contexts/_template.md` - 上下文模板
- ✅ `quality/standards/BY_DOCUMENT_TYPE.md` - 文档类型标准（按文档类型的专项审查标准）
- ✅ 各个实际文档

### 执行阶段

**方式 A: AI 辅助批量生成（推荐）**

#### 步骤 1: 新建 AI 会话（每次处理 5-10 个文档）

```
【发送给AI】

我需要批量生成框架文档的审查上下文。

【上下文1：模板】
[粘贴 quality/contexts/_template.md 完整内容]

【上下文2：文档类型标准（可选）】
[粘贴 quality/standards/BY_DOCUMENT_TYPE.md 中对应文档类型的专项标准]

【上下文3：实际文档】
当前要生成审查上下文的文档是：[文档名]
[粘贴实际文档的前100行或关键章节]

【任务】
请基于模板和实际文档内容，生成这个文档的审查上下文。
要求：
1. 严格遵循模板格式
2. 信息基于实际文档内容，不臆测
3. 明确文档定位、核心职责、关联文档
4. 提供具体的检查要点
```

#### 步骤 2: 验证生成的上下文

对每个生成的上下文进行检查：

- [ ] 文件路径正确

- [ ] 必须包含的内容完整
- [ ] 关联文档链接有效
- [ ] 检查要点具体可执行
- [ ] 格式符合模板

#### 步骤 3: 保存文件


## 🛠️ 批量生成技巧

### 技巧 1: 分批处理

**推荐分批策略**:

```
批次1: 入口文档（2个）
批次2: 核心规范文档（4个）
批次3: 工作流文档（7个）
批次4: 指导文档（6个）
批次5: 模板文档（10+个）
```

**原因**:

- 同类文档可以复用部分内容
- 避免 AI 会话 token 耗尽
- 便于质量检查

### 技巧 2: 使用占位符

对于重复性内容，先用占位符：

```markdown
**上游文档**: [待补充]
**下游文档**: [待补充]
```

批量生成后，再统一补充关联文档信息。

### 技巧 3: 质量抽检

不是每个上下文都需要 100%验证，可以：

- 每批抽检 2-3 个，全面检查
- 其他快速检查格式和必需字段
- 发现问题后，修正整批

### 技巧 4: 版本控制

```bash
# 每批完成后提交
git add quality/contexts/
git commit -m "feat: 生成批次X的审查上下文（文档类型Y）"
```

便于回滚和追溯。
