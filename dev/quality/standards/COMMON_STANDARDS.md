# 通用质量标准

> **用途**: 定义适用于所有框架文档的通用质量标准  
> **适用范围**: 入口文档、核心规范、工作流、指导文档、模板  
> **版本**: v1.0

---

## 📋 五大质量维度

### 1️⃣ 准确性 (Accuracy)

**定义**: 文档中的信息、代码示例、配置等内容准确无误

**检查要点**:

- [ ] **信息准确** - 所有陈述基于事实，无错误信息
- [ ] **代码示例准确** - 代码可直接运行无误，语法正确
- [ ] **API/函数签名准确** - API 调用、函数签名与实际代码一致
- [ ] **配置正确** - 配置项、路径、参数值正确
- [ ] **链接有效** - 所有超链接可访问，文档间引用正确
- [ ] **术语使用准确** - 专业术语使用正确，符合行业标准

**常见问题**:

- ❌ 代码示例中函数名与实际代码不一致
- ❌ 配置路径错误或过时
- ❌ 链接失效（文件被移动或删除）
- ❌ 技术术语误用

**验证方法**:

```
1. 代码示例 → 实际运行/与源代码对比
2. 配置项 → 查看实际配置文件
3. 链接 → 逐一点击验证
4. 技术术语 → 查阅权威资料
```

---

### 2️⃣ 完整性 (Completeness)

**定义**: 文档覆盖所有必要的信息点，无关键遗漏

**检查要点**:

- [ ] **核心概念完整** - 所有核心概念都有说明
- [ ] **关键场景覆盖** - 典型使用场景都有示例
- [ ] **必需章节齐全** - 按文档类型包含所有必需章节
- [ ] **示例充分** - 每个重要概念都有代码示例
- [ ] **边界情况说明** - 异常情况、边界条件有说明
- [ ] **前置条件明确** - 依赖、前置知识明确列出

**常见问题**:

- ❌ 只说明正常流程，未说明异常处理
- ❌ 概念解释抽象，缺少具体示例
- ❌ 缺少"何时使用"、"何时不使用"说明
- ❌ 未说明与其他文档的关联

**验证方法**:

```
1. 对比文档类型标准 → 检查必需章节
2. 枚举典型场景 → 检查是否都覆盖
3. 5W1H检查 → What、Why、When、Where、Who、How
```

---

### 3️⃣ 一致性 (Consistency)

**定义**: 文档内部及与其他文档之间术语、格式、风格统一

**检查要点**:

#### 术语一致性

- [ ] **术语统一** - 同一概念使用统一术语（如 "用户 ID" vs "userId"）
- [ ] **大小写一致** - 专有名词大小写统一（如 "GitHub" vs "github"）
- [ ] **缩写规范** - 首次出现时全称+缩写，后续统一使用

#### 格式一致性

- [ ] **标题层级** - 章节标题层级正确（# ## ### ####）
- [ ] **列表格式** - 无序/有序列表格式统一
- [ ] **代码块格式** - 统一使用```语言标识
- [ ] **表格格式** - 表格对齐方式统一
- [ ] **链接格式** - 文档间链接格式统一

#### 风格一致性

- [ ] **语气统一** - 保持一致的叙述语气（指导性/说明性）
- [ ] **人称统一** - "你"、"您"、"用户"等人称统一
- [ ] **时态统一** - 中文文档注意时态表达一致

**常见问题**:

- ❌ 同一概念在不同地方使用不同术语
- ❌ 标题层级跳跃（从## 直接到####）
- ❌ 代码块有的用```有的不用
- ❌ 一会儿"你"一会儿"您"

**验证方法**:

```
1. 术语检查 → 全文搜索同类概念，检查用词
2. 格式检查 → 目视检查或使用Markdown linter
3. 风格检查 → 通读，检查语气是否一致
```

---

### 4️⃣ 可读性 (Readability)

**定义**: 文档结构清晰，表述简洁，易于理解和查找

**检查要点**:

#### 结构清晰

- [ ] **逻辑流畅** - 章节顺序符合认知逻辑（从简单到复杂）
- [ ] **层次分明** - 使用标题、列表、引用区分层次
- [ ] **目录完整** - 长文档有 TOC，便于跳转
- [ ] **重点突出** - 使用加粗、引用框、表格突出重点

#### 表述简洁

- [ ] **语言简洁** - 避免冗余表述和废话
- [ ] **段落适中** - 段落长度适中（≤200 字/段）
- [ ] **句子清晰** - 长句拆分，避免歧义
- [ ] **主动语态** - 优先使用主动语态

#### 可视化辅助

- [ ] **图表辅助** - 复杂流程用 Mermaid 图表
- [ ] **表格对比** - 多维度对比用表格
- [ ] **代码高亮** - 代码块有语言标识
- [ ] **视觉标记** - 使用 emoji、符号增强可读性

**常见问题**:

- ❌ 一个段落几百字，密密麻麻
- ❌ 复杂流程用文字描述，无图表
- ❌ 重要信息淹没在大段文字中
- ❌ 长句套长句，难以理解

**验证方法**:

```
1. 5秒测试 → 打开文档，5秒内能否知道讲什么
2. 扫读测试 → 快速扫读标题，能否把握大意
3. 查找测试 → 模拟查找某信息，能否快速定位
```

---

### 5️⃣ 可操作性 (Actionability)

**定义**: 文档提供的指导明确、具体，用户可直接按步骤执行

**检查要点**:

#### 指令明确

- [ ] **步骤编号** - 操作步骤有序号
- [ ] **动词明确** - 使用明确的动作动词（复制、粘贴、运行）
- [ ] **条件明确** - "如果...则..."条件清晰
- [ ] **预期结果** - 说明执行后的预期效果

#### 示例具体

- [ ] **完整示例** - 代码示例完整可运行
- [ ] **注释充分** - 关键代码有注释说明
- [ ] **路径具体** - 文件路径、配置路径具体
- [ ] **命令可复制** - 命令可直接复制粘贴

#### 降低门槛

- [ ] **前置条件** - 列出必需的前置知识/工具
- [ ] **常见错误** - 列出常见错误和解决方法
- [ ] **检查点** - 提供检查步骤是否正确的方法

**常见问题**:

- ❌ 步骤模糊："配置相关设置"（哪些设置？怎么配？）
- ❌ 示例代码不完整，缺少 import
- ❌ 路径用占位符但未说明如何替换
- ❌ 缺少"如何验证配置是否成功"

**验证方法**:

```
1. 新手测试 → 假设完全不了解，能否按文档操作成功
2. 示例运行 → 实际运行每个代码示例
3. 完整性检查 → 检查是否缺少必要步骤
```

## 📊 质量评分标准

### 评分等级

**9-10 分 (优秀)**:

- 所有 5 个维度都优秀
- 几乎无需改进
- 可作为标杆文档

**7-8 分 (良好)**:

- 4 个维度优秀，1 个维度良好
- 有小问题但不影响使用
- 需要微调

**5-6 分 (及格)**:

- 3 个维度良好，2 个维度有问题
- 能用但体验不佳
- 需要改进

**3-4 分 (较差)**:

- 多个维度有明显问题
- 使用困难
- 需要大改

**1-2 分 (极差)**:

- 大多数维度严重问题
- 几乎不可用
- 需要重写

### 单维度评分

- ✅ **优秀**: 无明显问题
- ⚠️ **良好**: 有 1-2 个小问题
- ❌ **较差**: 有 3+问题或 1 个严重问题

## 🛠️ 使用方法

### 审查时使用

```
1. 打开质量检查清单
2. 对照5个维度逐一检查
3. 记录发现的问题
4. 按优先级修复
5. 重新检查
```

### 编写时使用

```
1. 写作前阅读质量标准
2. 写作时对照标准自查
3. 完成后全面检查
```
