# 文档审查工作流

> **用途**: 定义标准化的文档审查流程  
> **适用**: 人工阅读 + AI 互动的审查方式  
> **版本**: v1.0

---

## 🔄 标准审查流程

### 步骤 1: 选择要审查的文档

**确定审查范围**:

- 单个文档审查
- 某类文档批量审查
- 全框架文档审查

**优先级建议**:

1. P0: 入口文档（AI_ENTRY_POINT.md, README.md）
2. P1: 核心规范文档（core/\*.md）
3. P2: 工作流文档（workflows/\*.md）
4. P3: 指导文档（guides/\*.md）
5. P4: 模板文档（templates/\*.md）

### 步骤 2: 准备审查上下文

**需要准备的材料**:

1. **全局上下文**: `dev/FRAMEWORK_CONTEXT.md`
2. **文档审查上下文**: `dev/quality/contexts/[文档名].md`
3. **质量标准**（可选参考）:
   - `dev/quality/standards/COMMON_STANDARDS.md`
   - `dev/quality/standards/QUALITY_CHECKLIST.md`
4. **实际文档内容**: 要审查的文档

### 步骤 3: 新建 AI 会话窗口

**为什么要新建会话**?

- 避免历史对话干扰
- 确保纯净的审查视角
- 每个文档独立审查，互不影响

**会话配置**:

- 模型: 选择高能力模型（如 Claude 3.5 Sonnet）
- 温度: 0.3-0.5（保持专注和准确）

### 步骤 4: 发送审查上下文

**发送顺序**（重要）:

```
1️⃣ 发送全局上下文
【复制粘贴 dev/FRAMEWORK_CONTEXT.md 完整内容】
提示词: "这是框架的全局上下文，请先理解。"

2️⃣ 发送文档审查上下文
【复制粘贴 quality/contexts/xxx.md 完整内容】
提示词: "这是当前要审查的文档的审查上下文。"

3️⃣ 发送实际文档内容
【复制粘贴要审查的文档内容】
提示词: "请基于以上上下文，对这份文档进行最细颗粒度的优化审查。"
```

### 步骤 5: AI 分析并提供建议

**AI 应该提供的内容**:

1. **整体评估**

   - 文档质量得分（1-10）
   - 主要优点
   - 主要问题

2. **分类问题清单**

   - 准确性问题
   - 完整性问题
   - 一致性问题
   - 可读性问题
   - 可操作性问题

3. **具体优化建议**

   - 问题位置（章节、行号）
   - 问题描述
   - 修改建议
   - 优先级（高、中、低）

4. **质量检查清单评估**
   - 对照质量检查清单逐项检查
   - 标注未通过的项目

### 步骤 6: 人工审核 AI 建议

**审核标准**:

- ✅ **接受**: 问题确实存在，建议合理
- ⚠️ **部分接受**: 问题存在，但建议需调整
- ❌ **拒绝**: 误判或建议不合理

**决策原则**:

- 准确性问题 → 必须修复
- 完整性问题 → 优先修复
- 一致性问题 → 根据重要性决定
- 可读性问题 → 可优化
- 格式问题 → 批量处理

### 步骤 7: 执行优化

**执行方式**:

#### 方式 A: AI 辅助执行

```
【继续在同一会话中】
"请按照以下优化建议修改文档：
1. [建议1]
2. [建议2]
..."

AI生成修改后的完整文档
→ 人工审核
→ 确认无误后替换原文档
```

#### 方式 B: 人工执行

```
根据AI提供的建议清单
→ 人工逐项修改
→ 使用质量检查清单验证
```

**建议**: 重大修改用方式 A，小修改用方式 B

### 步骤 8: 验证修改

**验证清单**:

- [ ] 修改后的内容准确无误
- [ ] 所有建议都已处理（接受/拒绝）
- [ ] 文档格式正确
- [ ] 链接全部有效
- [ ] 对照质量检查清单全部通过

### 步骤 9: 记录审查报告（可选）

**报告内容**:

```markdown
# [文档名] 审查报告

**审查日期**: YYYY-MM-DD
**审查者**: [姓名]
**文档版本**: vX.X
**AI 模型**: [模型名称]

## 整体评估

- 审查前质量得分: X/10
- 审查后质量得分: X/10
- 发现问题数: X 个
- 修复问题数: X 个

## 主要问题

1. [问题类别]: [问题描述] → [处理方式]
2. ...

## 优化效果

- [优化点 1]
- [优化点 2]

## 遗留问题

- [问题 1]: [原因]

## 建议

- [建议 1]
```

**保存位置**: `dev/quality/audits/YYYY-MM-DD_<scope>.md`（轻量单文档审查采用 loose-file 形式，无需建目录；`<scope>` 用下划线连接的简明范围标签，如 `2026-05-18_dayflow_phase1_aicc_improvement_verification.md`）。完整 round 审查则归档为 `audits/YYYY-MM-DD_Version_Scope/` 目录含 5 件套——两种形式详见 [`audits/README.md`](./audits/README.md)。

## 📋 质量检查清单

每次审查时对照此清单：

### 内容质量

- [ ] 信息准确无误
- [ ] 无歧义表述
- [ ] 覆盖所有关键点
- [ ] 示例完整可用
- [ ] 无过时信息

### 结构清晰度

- [ ] 章节逻辑清晰
- [ ] 标题层级正确
- [ ] TOC 完整准确
- [ ] 重点突出

### 一致性

- [ ] 术语统一
- [ ] 格式统一
- [ ] 风格一致
- [ ] 链接有效

### 可操作性

- [ ] 指令明确
- [ ] 步骤完整
- [ ] 示例具体
- [ ] 可直接执行

### 引用正确性

- [ ] 文档间引用正确
- [ ] 文件路径准确
- [ ] 行号引用有效（如有）
- [ ] 无断链

## 💡 最佳实践

### 1. 批量审查策略

**同类文档批量审查**:

```
1. 创建批量审查计划
2. 为每个文档新建独立会话
3. 使用统一的审查标准
4. 记录共性问题
5. 批量处理共性问题
```

**优势**: 提升效率，发现系统性问题

### 2. 迭代审查

**第一轮**: 快速审查

- 关注重大问题（准确性、完整性）
- 快速修复

**第二轮**: 细节审查

- 关注一致性、可读性
- 精细打磨

### 3. 审查记录管理

**建议**:

- 每次全框架审查（如 V3.0 发布前）→ 完整审查报告
- 单个文档临时审查 → 简单记录或不记录
- 定期审查（如季度）→ 摘要报告

### 4. 质量改进循环

```
审查 → 发现问题 → 修复 → 验证 → 沉淀经验 → 优化标准
```

将共性问题沉淀为质量标准，持续改进。

## ⚠️ 注意事项

### 避免过度审查

- 不要追求完美，适度即可
- 区分"必须修复"和"可以优化"
- 控制审查时间（大文档 ≤2 小时）

### 保持客观

- 以质量标准为依据
- 避免主观偏好
- 事实为准

### AI 局限性

- AI 可能误判
- AI 建议需人工审核
- 关键决策由人类做

### 版本控制

- 审查前备份原文档
- 重大修改使用 git 提交
- 便于回滚
