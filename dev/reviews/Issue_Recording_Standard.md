# 问题记录标准与模板

本文档定义了AI Coding Context框架审查过程中问题记录的标准与规范，确保问题记录的一致性、完整性和可追溯性。

## 问题记录标准与规范

### 问题记录要素
每个发现的问题必须包含以下要素：
1. **问题ID**：唯一标识符，格式为`PROJ-YYYYMMDD-XXX`
2. **问题类型**：代码问题、文档问题、设计问题、集成问题、性能问题等
3. **严重级别**：严重、主要、次要、建议
4. **问题描述**：清晰、准确的问题描述
5. **影响范围**：问题影响的功能、组件或系统范围
6. **主要文件路径**：存在问题的核心文件或文档的完整路径
7. **相关文件路径**：与问题相关的其他文件或文档的完整路径列表
8. **具体位置**：文件中的具体位置（行号、章节号、代码片段等）
9. **复现步骤**：如何复现问题的详细步骤
10. **截图/证据**：截图、日志、测试结果等证据文件路径
11. **建议修复方案**：推荐的修复方法或改进建议
12. **优先级**：修复的优先级建议
13. **关联任务**：如果是特定任务相关，标注对应的任务编号
14. **审查阶段**：发现问题时的审查阶段

### 问题分类标准
- **代码问题**：逻辑错误、性能问题、安全漏洞、编码规范问题等
- **文档问题**：文档不一致、内容错误、缺失、过时等
- **设计问题**：架构设计不合理、设计模式使用不当等
- **集成问题**：组件间交互问题、接口不匹配、依赖问题等
- **性能问题**：性能瓶颈、资源使用不合理等
- **安全问题**：安全漏洞、权限问题、数据泄露风险等
- **用户体验问题**：使用流程不顺畅、界面交互不友好等

### 严重级别定义
- **严重**：导致系统崩溃、核心功能无法使用、安全漏洞等
- **主要**：功能异常、性能严重下降、重要文档错误等
- **次要**：功能小问题、性能轻微影响、文档不准确等
- **建议**：改进建议、优化建议、非必要的小问题等

### 问题记录工具与流程
1. **问题收集**：审查过程中实时记录问题到《问题跟踪表》
2. **问题整理**：每日整理当日发现的问题，按照模板完善记录
3. **问题分类**：按照问题分类标准对问题进行分类
4. **问题去重**：检查是否存在重复或相似问题，进行合并或关联
5. **问题验证**：对问题进行二次验证，确保问题真实存在
6. **问题归档**：将问题记录保存到审查文档目录的问题跟踪文件中
