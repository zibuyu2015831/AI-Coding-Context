# 《项目类型文档拆分方案》

> **提案日期**: 2026-01-21  
> **提案人**: AI Assistant  
> **目标**: 优化 `core/project_types.md` 的结构，实现按需加载

---

## 🎯 核心建议

**推荐方案**: **混合方案（方案 C）**

### 为什么选择混合方案？

1. **符合框架设计理念**
   - AI_ENTRY_POINT.md 第 26 行明确要求："按需加载原则：不得一次性读取大量子文档"
   - 当前 project_types.md 有 582 行，包含 11 种项目类型的详细信息
   - 实际使用时，AI 只需要其中 1-2 种项目类型的信息

2. **优化 Token 使用**
   - **当前**: 一次性加载 ~15KB 内容
   - **优化后**: 索引文档 ~3KB + 单个项目类型 ~1.5KB = ~4.5KB
   - **节省**: 约 70% 的 Token 消耗

3. **提升 AI 效率**
   - 减少认知负荷
   - 加快决策速度
   - 降低错误率

4. **保持易用性**
   - 索引文档提供快速决策树
   - 人类用户仍可查看完整信息
   - 维护成本可控
