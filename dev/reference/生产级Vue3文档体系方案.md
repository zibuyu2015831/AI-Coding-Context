# AI 辅助开发文档生成 - 执行方案（v2.0 优化版）

## 任务概述

为 Vue3 前端项目（288 个 Vue 文件 + 135 个 TS/JS 文件）生成完整的 AI 编码上下文文档体系，帮助后续 AI 辅助开发快速理解项目结构、复用代码、保持开发规范。

## 任务复杂度评估

### 复杂度：⭐⭐⭐⭐⭐ (高难度)

**原因分析：**

1. **代码规模庞大**

   - 288 个 Vue 组件文件，平均每个文件需要 3-5 分钟分析
   - 135 个 TypeScript/JavaScript 文件
   - 总计约 423 个源码文件

2. **多模块业务系统**

   - 至少 10+个业务模块（project, scan, vulnerability, compliance, component, admin, report 等）
   - 每个模块都有独立的 API 层、Store 层、View 层
   - 需要理解各模块间的数据流和依赖关系

3. **特殊架构设计**

   - 多品牌/多租户架构（支持 catarc/mstl/anesec/osredm/306 等品牌）
   - 复杂的配置系统（环境变量 + 构建时覆盖 + 运行时覆盖）
   - 动态路由和动态组件加载

4. **文档体系复杂**
   - 需要生成 1 个主文档 + 10 个子文档
   - 每个文档都需要深入分析代码
   - 需要维护文档间的交叉引用

**预计工作量：** 4-6 小时（包含中间审查和可能的返工时间）

**风险点：**

- 某些文件可能非常大，需要多次读取和分析
- 项目依赖关系复杂，可能遗漏重要信息
- 需要平衡详细度和可读性

## 交互策略与原则

### 1. AI 交互策略

**阶段性确认：**

- 完成阶段一后，请求用户审查扫描结果
- 完成阶段三（核心文档）后，请求用户审查质量再继续
- 发现重大架构问题时，及时与用户沟通

**大文件处理策略：**

- 超过 800 行的文件先使用 `view_file_outline` 了解结构
- 根据 outline 结果决定需要详细读取的部分
- 分段读取时优先读取关键函数和配置部分

**复杂模块处理：**

- 先绘制模块依赖关系图（使用 mermaid）
- 提供中间产出物供用户审查
- 必要时请求用户提供业务背景说明

### 2. 文档生成原则

**代码示例要求：**

- 所有代码示例必须来自真实项目代码（不编造）
- 每个示例都要注明来源文件路径
- 复杂示例要有注释说明

**链接格式规范：**

- 文件路径使用 markdown 链接格式：`[filename](file:///absolute/path)`
- 跨文档引用使用相对路径：`[文档名](./other_doc.md)`
- 外部资源使用完整 URL

**可视化要求：**

- 使用 mermaid 图表可视化复杂关系（架构图、流程图、依赖图）
- 配置系统必须有流程图
- 数据关系必须有实体关系图（ER 图）

**格式要求：**

- 使用 GitHub Flavored Markdown
- 代码块指定语言类型（vue, typescript, javascript 等）
- 使用表格组织结构化信息
- 使用 alert 块强调重要信息（> [!IMPORTANT]等）
