### P0-1: 补充敏感信息脱敏示例

**问题描述**: `core/security_rules.md` 有规范但缺少具体代码示例，AI 可能不知道如何具体执行

**影响**:

- 风险等级: 中高
- 影响范围: 所有项目的文档生成
- 可能后果: 敏感信息泄露到文档中

**优化方案**:

1. **在 `core/security_rules.md` 中补充实际示例**

````markdown
### 密钥脱敏示例

**原始代码**:

```python
# ❌ 不安全 - 硬编码密钥
API_KEY = "sk_live_1234567890abcdefghijklmnop"
DATABASE_URL = "postgresql://user:password123@localhost/db"
```
````

**文档中应该这样写**:

```python
# ✅ 安全 - 使用环境变量
API_KEY = os.getenv("API_KEY")  # 从环境变量读取
DATABASE_URL = os.getenv("DATABASE_URL")  # 实际密码已脱敏
```

**说明要求**:

- 密钥来源: 环境变量 `.env` 文件
- 配置示例: 见 `.env.example`

2. **补充常见敏感信息清单**

| 类型        | 识别特征                            | 脱敏方式                | 示例 |
| ----------- | ----------------------------------- | ----------------------- | ---- |
| API 密钥    | `API_KEY`, `SECRET_KEY`, `sk_live_` | 用`os.getenv()`替代     | ✅   |
| 数据库密码  | 连接字符串中的密码字段              | 显示`***`或指向配置     | ✅   |
| JWT Secret  | `JWT_SECRET`, `TOKEN_SECRET`        | 完全隐藏，说明来源      | ✅   |
| 云服务凭证  | AWS_ACCESS_KEY, GCP_KEY             | 引用 IAM 角色或凭证文件 | ✅   |
| OAuth Token | access_token, refresh_token         | 说明获取方式，不展示    | ✅   |

**预计工时**: 2 小时
**验收标准**:

- [ ] 至少包含 5 种敏感信息类型的示例
- [ ] 每种都有"错误示例"和"正确示例"
- [ ] 提供 AI 可理解的检测规则

### P0-2: 补充多语言项目主语言判断标准

**问题描述**: 提到"识别主要语言和次要语言"，但判断标准不够明确

**影响**:

- AI 可能误判项目主语言
- 影响文档生成策略选择
- 用户需要手动干预

**优化方案**:

在 `workflows/detection_workflow.md` 中补充：

````markdown
### 1.5 多语言项目主语言判断

**判断标准**（按优先级）:

1. **代码行数占比** (权重: 60%)

   - 主语言: 代码行数 > 60% 总代码量
   - 次要语言: 10% < 代码行数 < 60%
   - 辅助语言: 代码行数 < 10%

2. **项目类型特征** (权重: 30%)

   - 前端项目: 优先 JavaScript/TypeScript
   - 后端项目: 优先 Python/Java/Go
   - 全栈项目: 分别判断前后端主语言

3. **框架依赖** (权重: 10%)
   - 检测到主流框架配置文件优先其语言
   - 如: package.json → JavaScript/TypeScript

**判断流程**:

```bash
# 1. 统计各语言代码行数
tokei --output json | jq '.languages'

# 2. 计算占比
总代码量 = 所有语言代码行数之和
各语言占比 = 该语言代码行数 / 总代码量 * 100%

# 3. 应用判断规则
if 某语言占比 > 60%:
    主语言 = 该语言
elif 无语言占比 > 60% and 项目类型明确:
    主语言 = 项目类型默认语言
else:
    询问用户确认主语言
```
````

**示例输出**:

```markdown
📊 语言分布检测结果:

| 语言       | 代码行数 | 占比 | 分类     |
| ---------- | -------- | ---- | -------- |
| Python     | 8,500    | 68%  | 主语言   |
| JavaScript | 2,800    | 22%  | 次要语言 |
| Shell      | 850      | 7%   | 辅助语言 |
| YAML       | 350      | 3%   | 配置     |

**判断结果**: 主语言 = Python (代码占比 68% > 60%)
```

**预计工时**: 2 小时
**验收标准**:

- [ ] 明确的数值判断标准
- [ ] 多语言场景决策流程图
- [ ] 边缘情况处理说明

````markdown
# AI Rules 维护指南

## 📋 概述

AI Rules 文件(`dev_docs/rules/combined/AI_RULES.md`)是 IDE 中 AI 遵守的规则集。
本指南说明何时更新、如何更新 Rules 文件。

## 🕐 更新时机

### 必须更新（关键变更）

1. **架构重构**

   - 示例: 从单体应用迁移到微服务
   - 操作: 更新架构相关 rules

2. **技术栈升级**

   - 示例: Vue 2 → Vue 3
   - 操作: 更新框架相关 rules 和 API 用法

3. **新增核心模块**

   - 示例: 新增支付模块
   - 操作: 添加该模块的开发规范

4. **编码规范变更**
   - 示例: 采用新的命名规范
   - 操作: 更新代码风格 rules

### 建议更新（重要变更）

1. **新功能上线**（影响 > 3 个文件）
2. **依赖项重大升级**（如: React 17 → 18）
3. **API 设计变更**
4. **数据库 Schema 重大调整**

### 可选更新（次要变更）

1. 小 bug 修复
2. 文案调整
3. 样式微调

## 🔄 更新流程

### 方式 1: 让 AI 重新生成（推荐）

**适用**: 大规模重构或多处变更

请按照最新的项目代码，重新生成 dev_docs/rules/combined/AI_RULES.md

请注意以下变更：

- [列出主要变更点]

### 方式 2: 手动增量更新

**适用**: 小范围更新

```markdown
1. 定位需要修改的 section
2. 更新具体规则
3. 保持格式一致
4. 测试 AI 是否理解新规则
```
````

### 方式 3: 模块化更新（v2.2+）

**适用**: 独立规范变更

```
请更新 dev_docs/rules/core/api_design.md
然后重新组合生成 AI_RULES.md
```

## ✅ 更新检查清单

更新后确认：

- [ ] 新规则不与现有规则冲突
- [ ] 关键规则用加粗或标注强调

### P2-1: 创建快速诊断工具

**问题描述**: 用户可能不知道框架是否正确安装/配置

**优化方案**: 创建诊断脚本 `scripts/diagnose.sh`

**功能**:

```bash
#!/bin/bash
# Framework Diagnostic Tool

echo "🔍 AI Coding Context 诊断工具"
echo "======================================"

# 1. 检查目录结构
echo "📂 检查框架目录结构..."
[ -f "AI_ENTRY_POINT.md" ] && echo "✅ AI_ENTRY_POINT.md" || echo "❌ 缺失"
[ -d "core" ] && echo "✅ core/" || echo "❌ 缺失"
[ -d "workflows" ] && echo "✅ workflows/" || echo "❌ 缺失"

# 2. 检查工具可用性
echo ""
echo "🔧 检查统计工具..."
which tokei >/dev/null 2>&1 && echo "✅ tokei可用" || echo "⚠️  tokei未安装（推荐）"
which cloc >/dev/null 2>&1 && echo "✅ cloc可用" || echo "ℹ️  cloc未安装"

# 3. 检查项目状态
echo ""
echo "📊 检查项目状态..."
if [ -d "dev_docs" ]; then
    echo "✅ dev_docs/ 已创建"
    [ -f "dev_docs/AI_Coding_Context.md" ] && echo "  ✅ 主文档已生成" || echo "  ℹ️  主文档未生成"
else
    echo "ℹ️  dev_docs/ 未创建（尚未生成文档）"
fi

echo ""
echo "📋 诊断完成"
```

**预计工时**: 2 小时
