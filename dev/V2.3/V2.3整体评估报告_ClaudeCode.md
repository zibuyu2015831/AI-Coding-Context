#### 2.2.2 文档健康度检查 (workflows/document_health_check.md)

**评级**: ⭐⭐⭐⭐⭐ (5/5)

**v2.3核心创新**，最具核心价值！

**3种模式设计**:
```markdown
模式1: 快速扫描 ⚡ (~50 tokens, ~1分钟)
  └─ 适用: 快速评估

模式2: 标准检查 ⭐ (~200-300 tokens, 3-5分钟) **推荐**
  └─ 适用: 常规评估（Git采样检查）

模式3: 深度分析 🔍 (~800-1000 tokens, 10-15分钟)
  └─ 适用: 长期未更新或重大变更后
```

**百分制评分模型**：100%-扣分设计非常直观，但发现一处字符异常——在files_with_matches中负号-后面缺少空格导致前端展示异常。

**扣分项A (时间衰减)**:
```
0-1月: 0分 | 1-2月: -5分 | 2-3月: -10分 | 3-6月: -20分 | >6月: -30分
```

**扣分项B (代码变更)**:
- 细致到文件类型（核心入口/核心模块/业务模块/工具类/配置文件等）
- 动作触发区分（新增/修改/删除），权重合理

**扣分项C (覆盖率)**:
```
+>20文件: -20分 | +10-20: -15分 | +5-10: -10分 | +<5: -5分
```

**健康度等级**:
```
90-100: 🟢 优秀（无需更新）
70-89: 🟡 良好（选择性更新）
50-69: 🟠 一般（增量更新）
30-49: 🔴 较差（全量更新）
<30: ⛔ 极差（必须重新生成）
```

**创新设计**: 双向时间对比帮助识别历史项目，避免误判。这在处理遗留代码时极具价值。

**Hot Topics**: 文档提供降级策略4级（Git diff → 文件时间对比 → 用户提供信息 → 仅时间），适配无Git环境的边缘排查场景。

**负面反馈**: 暂无，设计严谨，nuances周全。

**技术实现**:
