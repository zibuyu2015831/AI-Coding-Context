## 📋 核心概念

> **关联优化点**: 017-实用脚本库

利用配置系统 (016) 的存储能力，建立运行时状态文件 `config/system_tracker.json`，用于记录高频操作，驱动工具沉淀。

## �💡 方案设计

### 1. 状态存储设计

**文件位置**: `config/.system/usage_stats.json` (隐藏目录，避免干扰用户)

**数据结构设计**:

> **设计说明**: 采用分层结构，将"命令执行"与"文件操作"分离，并引入 `signature` (签名) 概念以支持指纹识别。

```json
{
  "last_updated": "2025-12-01T12:00:00Z",
  "command_stats": {
    "complex_find_and_replace": {
      "signature": "find . -name '*.js' | xargs sed...",
      "count": 4,
      "last_used": "2025-12-01"
    },
    "log_analysis_pattern": {
      "signature": "grep 'Error' | awk ...",
      "count": 2,
      "last_used": "2025-11-30"
    }
  },
  "file_op_stats": {
    "bulk_rename": {
      "count": 3,
      "description": "Batch rename .js to .ts",
      "last_used": "2025-12-01"
    }
  },
  "tool_recommendations": [
    {
      "trigger": "complex_find_and_replace > 3",
      "action": "suggest_create_tool",
      "context": "Detected frequent manual find-and-replace operations"
    }
  ]
}
```

**结构优势分析**:

1.  **分类清晰**: `command_stats` 记录 Shell 命令，`file_op_stats` 记录文件系统操作，便于针对性分析。
2.  **指纹识别**: `signature` 字段为去重和归类提供了基础（例如通过正则模糊匹配相似命令）。
3.  **时间追踪**: `last_used` 和 `last_updated` 支持 LRU (最近最少使用) 清理策略，防止文件无限膨胀。

### 2. 工作流程

1.  **记录 (Record)**:

    - AI 在执行任务时，识别复杂或重复的操作（如复杂的 `find` 命令、多文件正则替换）。
    - 生成操作签名（Signature）。
    - 更新 `usage_stats.json` 中的计数器。

2.  **分析 (Analyze)**:

    - 每次会话开始时，或在空闲时间，检查 Tracker 数据。
    - 对比预设的阈值（例如：重复执行 > 3 次）。

3.  **触发 (Trigger)**:
    - 若满足阈值且尚未创建工具。
    - 提示用户："检测到您经常执行 X 操作，建议创建专用工具（参考 017 工作流）"。

### 3. 优势

- ✅ **跨会话记忆**: 即使开启新对话，历史操作数据依然保留。
- ✅ **数据驱动**: 基于实际使用频率推荐，而非 AI 臆测。
- ✅ **自动沉淀**: 让工具库随着项目发展自动生长。

## ⚠️ 待讨论问题 (Open Questions)

1.  **指纹识别 (Fingerprinting)**:

    - 如何准确判断两次操作是"同一类"？
    - 例如：参数不同的 `find` 命令是否归为一类？需要模糊匹配算法。

2.  **噪声控制**:

    - 如何避免 Tracker 文件无限膨胀？
    - 方案：引入白名单、LRU 清理机制或定期归档。

3.  **更新时机**:
    - 是实时更新（每次操作后写文件）还是会话结束时批量更新？
    - 实时更新更安全但有 I/O 开销；批量更新可能丢失数据。
