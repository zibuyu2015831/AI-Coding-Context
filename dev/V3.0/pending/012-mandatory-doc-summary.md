# 012 - 强制文档摘要机制

**优先级**: P0  
**状态**: 🟡 待讨论  
**预估工作量**: 5-7 天  
**来源**: 用户洞察 + Token 优化需求

---

## 📋 问题描述

### 核心痛点

1. **文档缺少摘要，导致效率低下**

   - 用户需要完整阅读才知道文档内容
   - AI 需要读取全文才能判断相关性
   - 认知负荷高，定位困难

2. **Token 消耗过高**

   - AI 每次都读取完整文档（平均 500 行）
   - 无法快速过滤不相关文档
   - 预估浪费 30-50% Token

3. **摘要格式不统一**
   - 部分文档有摘要，部分没有
   - 格式各异，难以自动化处理
   - 无法结构化提取摘要数据

### V2.3 现状

- ⚠️ 部分模板有摘要（如 `PROJECT_ANALYSIS_REPORT_TEMPLATE.md`）
- ❌ 未要求所有文档强制包含摘要
- ❌ 没有标准化的摘要格式
- ❌ 缺少摘要质量检查机制

---

## 💡 解决方案

### 方案设计

#### 标准化摘要格式（正则友好）

```markdown
<!-- SUMMARY_START -->

用途: [一句话说明，≤100 字符]
场景: [场景 1] | [场景 2] | [场景 3]
核心: [要点 1] | [要点 2] | [要点 3] | [要点 4] | [要点 5]
时长: [完整阅读 X 分钟]
依赖: [文档 1] | [文档 2] | [无]
判断: [快速判断条件，≤150 字符]
验证: [YYYY-MM-DD]

<!-- SUMMARY_END -->
```

**设计理念**:

1. **正则友好**: 使用 HTML 注释标记边界，便于提取
2. **固定字段**: 使用 `字段名:` 格式，便于解析
3. **分隔符统一**: 使用 `|` 分隔多个值
4. **长度限制**: 每个字段有明确的长度约束
5. **机器可读**: 可轻松转换为 JSON/YAML

#### 摘要字段说明

```markdown
必填字段:

- 用途: 一句话说明文档用途（≤100 字符）
- 场景: 2-3 个典型使用场景，用 | 分隔
- 核心: 3-5 个核心要点，用 | 分隔
- 时长: 预估完整阅读时间
- 依赖: 前置必读文档，用 | 分隔，无依赖写"无"
- 判断: 帮助用户快速判断是否需要阅读（≤150 字符）
- 验证: 摘要最后验证日期（YYYY-MM-DD）
```

### 实现方式

#### 1. 摘要自动生成

```markdown
场景 1: 初次生成文档

- AI 分析文档内容
- 自动生成标准化摘要
- 用户审核并调整

场景 2: 文档更新后

- AI 检测文档变化程度
- 如果变化 > 30%，提示更新摘要
- 用户确认或 AI 自动更新

场景 3: 用户手动创建文档

- 提供摘要模板
- AI 辅助填充
```

#### 2. 摘要质量检查

```markdown
自动检查项:

1. ✅ 所有必填字段都填写
2. ✅ 用途 ≤ 100 字符
3. ✅ 场景数量 = 2-3 个
4. ✅ 核心要点数量 = 3-5 个
5. ✅ 每个核心要点 ≤ 50 字符
6. ✅ 判断条件 ≤ 150 字符
7. ✅ 总长度 ≤ 500 字符
8. ✅ 验证日期格式正确
9. ✅ 可用正则提取

人工检查项:

1. 场景描述是否具体？（避免"各种场景"）
2. 核心要点是否准确？
3. 快速判断条件是否清晰？
```

#### 3. 摘要提取工具

```javascript
// summary_extractor.js

/**
 * 从 Markdown 文档中提取摘要
 */
function extractSummary(markdown) {
  const summaryRegex = /<!-- SUMMARY_START -->([\s\S]*?)<!-- SUMMARY_END -->/;
  const match = markdown.match(summaryRegex);

  if (!match) return null;

  const summaryText = match[1];

  return {
    usage: extractField(summaryText, "用途"),
    scenarios: extractField(summaryText, "场景")
      .split("|")
      .map((s) => s.trim()),
    corePoints: extractField(summaryText, "核心")
      .split("|")
      .map((s) => s.trim()),
    duration: extractField(summaryText, "时长"),
    dependencies: extractField(summaryText, "依赖")
      .split("|")
      .map((s) => s.trim()),
    criteria: extractField(summaryText, "判断"),
    verified: extractField(summaryText, "验证"),
  };
}

function extractField(text, fieldName) {
  const regex = new RegExp(`${fieldName}: (.+)`);
  const match = text.match(regex);
  return match ? match[1].trim() : "";
}

/**
 * 导出为 JSON
 */
function exportSummariesToJSON(docFiles) {
  const summaries = {};

  docFiles.forEach((file) => {
    const content = readFile(file);
    const summary = extractSummary(content);

    if (summary) {
      summaries[file] = summary;
    }
  });

  return JSON.stringify(summaries, null, 2);
}
```

#### 4. 摘要版本控制

```markdown
问题: 文档更新后，摘要可能过时

解决方案:

1. **验证日期字段**:

   - 摘要中包含"验证: YYYY-MM-DD"
   - 记录摘要最后验证日期

2. **自动过期提醒**:

   - 文档更新后，AI 检查验证日期
   - 如果 > 30 天且文档有重大变更，提示更新摘要

3. **变更阈值**:
   - 文档变更 < 10%: 无需更新摘要
   - 文档变更 10-30%: 建议更新摘要
   - 文档变更 > 30%: 强制更新摘要
```

#### 5. 智能文档推荐

```markdown
场景: 用户描述需求，AI 推荐相关文档

工作流:

1. 用户: "我要实现用户登录功能"

2. AI 快速扫描所有文档摘要（不读全文）

3. AI 匹配相关文档:

   - authentication.md: 匹配度 95% (场景包含"用户登录")
   - api_layer.md: 匹配度 80% (核心要点包含"API 调用")
   - error_handling.md: 匹配度 70% (登录需要错误处理)
   - database_schema.md: 匹配度 30% (相关性低，排除)

4. AI 推荐阅读顺序和优先级:
   - 必读: authentication.md (15 分钟)
   - 建议: api_layer.md (15 分钟)
   - 可选: error_handling.md (10 分钟)

Token 节省:

- 传统: 读 10 个文档 × 500 行 = 5000 行
- 摘要: 读 10 个摘要 + 3 个全文 = 100 + 1500 = 1600 行
- 节省: 68% Token
```

4. **标准化格式** - 便于自动化处理
5. **智能推荐** - 基于摘要匹配相关文档

## ⚠️ 风险与疑问

### 需要讨论的问题

1. **❓ 摘要格式是否足够简洁？**

   - 7 个字段是否太多？
   - 是否需要简化版和完整版？

2. **❓ 长度限制是否合理？**

   - 总长度 500 字符是否够用？
   - 核心要点每个 50 字符是否太少？

3. **❓ 验证日期的更新策略**

   - 谁负责更新？（AI 自动 vs 手动）
   - 过期阈值 30 天是否合理？

4. **❓ 摘要提取工具的语言选择**

   - JavaScript/Python/其他？
   - 是否需要 CLI 工具？

5. **❓ 智能推荐的准确性**

   - 如何评估匹配度？
   - 是否需要机器学习模型？

6. **❓ 与现有模板的兼容性**
   - 如何更新现有 15 个模板？
   - 是否需要迁移工具？

### 潜在风险

| 风险               | 可能性 | 影响 | 应对措施                   |
| ------------------ | ------ | ---- | -------------------------- |
| 摘要质量不稳定     | 中     | 中   | 质量检查 + 人工审核        |
| 摘要过时           | 中     | 中   | 验证日期 + 自动提醒        |
| 格式解析失败       | 低     | 低   | 严格格式验证 + 错误提示    |
| 长度限制不够用     | 中     | 低   | 根据实际情况调整限制       |
| 用户不愿写摘要     | 中     | 高   | AI 自动生成 + 简化审核流程 |
| Token 节省未达预期 | 低     | 中   | 优化推荐算法               |
