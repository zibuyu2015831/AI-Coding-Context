## 📋 问题描述

### 核心痛点

1.  **非确定性**: 目前依赖 AI 通过 shell 命令 (如 `dir`, `ls`, `Get-Content`) 临时探索项目，容易受幻觉影响或遗漏文件。
2.  **效率低下**: AI 反复生成类似的探索命令，浪费 Token 和时间。
3.  **平台差异**: Windows/Linux/Mac 的命令差异导致 Prompt 难以统一。
4.  **结果解析难**: AI 需要花费 Token 去解析 `dir` 或 `ls` 的非结构化文本输出。

### V2.3 现状

- 依赖 `AI_ENTRY_POINT.md` 中的 Prompt 引导 AI 使用系统命令。
- 没有统一的、跨平台的、结构化的数据获取工具。

---

## 💡 解决方案

### 方案设计

建立一个标准化的 `tools/` 或 `scripts/` 目录，包含一组高可用、跨平台的脚本（优先 Python/Node.js），供 AI 在分析项目时直接调用。

## 🧠 头脑风暴：工具清单与跨平台策略

### 1. 核心工具清单 (Core Tools)

参考 Claude Code 的最佳实践，我们将工具集细化为以下核心组件：

| 工具名                 | 对应 Claude 工具    | 功能描述         | 关键特性 (借鉴点)                                                                  | 输入参数                                    |
| :--------------------- | :------------------ | :--------------- | :--------------------------------------------------------------------------------- | :------------------------------------------ |
| **`project_scanner`**  | `ListDirectoryTool` | 智能项目结构扫描 | **BFS 广度优先遍历** (防爆栈), **Tree 树状可视化输出** (AI 易读), `gitignore` 过滤 | `--path`, `--depth`, `--format` (json/tree) |
| **`file_reader`**      | `FileReadTool`      | 安全文件读取     | **分页读取** (`offset`/`limit`), 自动检测编码, 大文件截断警告                      | `--path`, `--offset`, `--limit`             |
| **`content_searcher`** | `GrepTool`          | 关键词/正则搜索  | **优先调用 `rg` (ripgrep)** (如果存在), 降级使用原生正则; 支持 `include` 模式过滤  | `--query`, `--regex`, `--include`, `--path` |
| **`file_finder`**      | `GlobTool`          | 文件名模式匹配   | 使用 `glob` 模式快速定位文件                                                       | `--pattern`, `--path`, `--limit`            |
| **`env_diagnosis`**    | N/A                 | 环境诊断         | 快速了解项目运行时环境                                                             | 无                                          |
| **`git_inspector`**    | N/A                 | Git 状态分析     | 结构化展示变更                                                                     | `--mode`                                    |

> **设计洞察**:
>
> 1. **分页读取**是处理大文件的关键，必须在 `file_reader` 中实现。
> 2. **树状输出** (Tree View) 比单纯的 JSON 列表更能帮助 AI 理解层级关系。
> 3. **Ripgrep** 的速度优势巨大，应作为 `content_searcher` 的首选后端，但需做好降级处理。

### 2. 跨平台与运行时策略 (Runtime Strategy)

考虑到用户环境的多样性，我们采用 **"双模 + 降级"** 策略：

#### 策略 A: 双模运行 (Dual-Mode Runtime) - **推荐**

同时提供 **Python** (`tools/py/`) 和 **Node.js** (`tools/js/`) 两套代码。

- **逻辑**: 这两种语言覆盖了 90%+ 的开发者环境。
- **机制**: AI 启动时先运行 `check_env`，优先使用 Python (通常标准库更丰富)，如果无 Python 则使用 Node.js。

#### 策略 B: 无环境降级 (No-Runtime Fallback)

如果用户既没有 Python 也没有 Node.js (极少见，但在纯 Go/Rust/C++ 环境可能发生)：

1.  **方案 1 (轻量级)**: **Shell 命令速查表 (Shell Cheat Sheet)**

    - 在 `tools/fallback/` 下提供 `commands_win.md` 和 `commands_unix.md`。
    - 包含经过验证的、输出最干净的系统原生命令组合 (PowerShell/Bash)。
    - _AI 必须严格遵守这些经过测试的命令，而不是自己发挥。_

2.  **方案 2 (重量级)**: **编译产物 (Binaries)**
    - 提供编译好的二进制文件 (如 Go 编写的 CLI)。
    - _缺点_: 增加仓库体积，不仅要存源码还要存二进制，不符合"轻量级框架"初衷。
    - _结论_: **暂不推荐**，除非用户强烈要求。

### 3. 实现细节

- **统一接口**: 无论 Python 还是 Node 版本，参数和输出 JSON 格式必须**完全一致**。
- **零依赖**: 脚本必须只使用**标准库**，严禁 `pip install` or `npm install`，确保"下载即用"。
- **错误处理**: 发生错误时必须返回 JSON 格式的错误信息，而不是抛出堆栈，方便 AI 自愈。

## � 框架集成 (Framework Integration)

此优化点实现后，将显著简化 `AI_ENTRY_POINT.md` 的流程：

### 1. 优化 "步骤 0: 环境预检" & "步骤 1: 项目检测"

- **现状**: 依赖 `tokei`/`cloc` 或复杂的跨平台 Shell 命令组合。
- **优化**: 统一替换为调用 `tools/project_scanner`。
- **收益**: 消除 OS 差异，确保 `.gitignore` 被遵守，直接获取 JSON 格式的精准统计。

### 2. 优化 "步骤 2: 策略决策"

- **现状**: AI 需人工解析统计结果来判断项目规模。
- **优化**: `project_scanner` 直接返回项目规模元数据 (文件数/行数)，AI 可直接映射到策略级别。

### 3. 优化 "数据验证"

- **现状**: AI 需构造 `find`/`grep` 命令来验证分析结论。
- **优化**: 统一使用 `tools/content_searcher` 进行精准验证。

### 4. 优化 "Token 消耗"

- **现状**: `dir /s` 或 `tree` 输出大量冗余文本。
- **优化**: `project_scanner` 的 Tree 视图或 JSON 输出经过压缩优化，大幅降低 Token 消耗。
