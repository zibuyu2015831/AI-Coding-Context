# 实施计划 - 013 AI 互审机制

## 目标描述

实施 **AI 互审机制 (AI Mutual Review)**，这是一个工作流编排器，旨在将“第二意见”引入 AI 编程流程中。该机制旨在通过基于任务复杂度和用户指令强制执行多级审查（快速、标准、深度），消除单一模型的盲点（“鬼打墙”）并提高代码质量。

系统将：

1.  **编排审查**: 根据用户指令 (`@review:xxx`) 或自动复杂度评估，决定是否审查以及审查的深度。
2.  **执行标准**: 根据任务类型应用特定的审查标准（功能、Bug 修复、重构）。
3.  **自动决策**: 根据可靠度评分和提升潜力，自动决定是否优化方案。

## 需要用户审查

> [!IMPORTANT] > **新用户指令**: 此更新引入了用户可用于控制审查流程的新指令：
>
> - `@review:standard`: 强制执行标准 1 轮审查。
> - `@review:deep`: 强制执行深度 2 轮审查。
> - `@review:skip`: 强制跳过审查。
> - `@urgent` / `@hotfix`: 跳过审查但标记为未审核。

> [!NOTE] > **配置**: 用户可以在 `config/user_config.md` 中自定义审查阈值和行为（待 016 完全集成后）。

### 2. 工作流逻辑实现 (`workflows/review-workflow.md`)

定义审查流程的核心逻辑，包括决策树、复杂度评估和可靠度判断。

#### [NEW] `workflows/review-workflow.md`

**A. 复杂度评估逻辑 (混合模式)**

- **静态分析 (40%)**:
  - 文件数量 (≥10: 40 分, ≥5: 25 分)
  - 代码行数 (≥500: 30 分, ≥200: 15 分)
  - 核心模块修改 (auth/, payment/ 等: +20 分)
  - 破坏性变更 (+10 分)
- **AI 语义分析 (60%)**: 基于业务逻辑复杂度、语义风险、上下文相关性。
- **分级**:
  - 简单 (0-30): 跳过审查
  - 中等 (31-65): 标准审查 (1 轮)
  - 复杂 (66-100): 深度审查 (2 轮)

**B. 可靠度驱动决策逻辑**

- **元数据定义**:
  - `plan_metadata`: 包含 `reliability` (0-100), `risk_level`, `breaking_change`, `complexity_score`.
  - `review_metadata`: 包含 `improvement_potential`, `confidence_level`, `p0_issues`, `has_controversial_suggestions`.
- **自动优化规则**:
  - 触发条件: 原方案可靠度 < 60 或 提升潜力 ≥ 20.
  - **边界条件 (强制人工介入)**:
    - 发现 P0 严重问题.
    - 涉及破坏性变更.
    - 审核者置信度 < 0.6.
    - 存在争议性建议.
    - 审核后可靠度反降.

### 4. 风险管理与异常处理

#### 风险缓解策略

- **AI 误判风险**: 引入“置信度”指标，低置信度时强制人工复核。
- **Token 消耗**: 简单任务跳过审查，限制最大优化轮数为 1 轮。
- **审查耗时**: 异步执行审查（如支持），或在用户阅读方案时并行进行（未来优化）。
- **意见冲突**: 以“可靠度提升”为唯一标准，若提升不明显则维持原判。

#### 异常处理机制

- **审查超时**: 若审查过程超过 2 分钟，自动降级为“跳过审查”并提示用户。
- **JSON 解析失败**: 若元数据解析失败，默认视为“中等复杂度”进行标准审查。
- **死循环保护**: 严格限制自动优化仅执行 1 轮，防止 AI 陷入自我纠正循环。
- **Token 耗尽**: 捕获 Token 溢出错误，自动切换到精简模式或仅输出摘要。

## 验证计划

### 手动验证场景

1.  **场景 A: 明确跳过**

    - 操作: 请求一个简单的更改并附带 `@review:skip`。
    - 预期: AI 识别指令，跳过复杂度评估，直接输出方案。

2.  **场景 B: 强制深度审查**

    - 操作: 请求一个功能并附带 `@review:deep`。
    - 预期: AI 生成方案，执行第 1 轮标准审查，执行第 2 轮深度审查，输出包含两轮报告的最终结果。

3.  **场景 C: 自动复杂度触发**

    - 操作: 请求一个复杂的重构（涉及 `auth/`, `payment/` 等核心模块），不带特定指令。
    - 预期: 静态分析识别核心模块修改，AI 评估语义复杂，总分 > 65，自动触发深度审查。

4.  **场景 D: 自动优化与边界条件**
    - 操作: 模拟一个低质量方案 (可靠度 < 60) 或存在 P0 问题的方案。
    - 预期:
      - 低可靠度: 自动触发优化循环，生成 v2 方案。
      - P0 问题: 即使提升潜力大，也强制停止自动优化，提示用户人工确认严重问题。
