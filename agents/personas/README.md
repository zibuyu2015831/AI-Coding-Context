# Personas - 人格型 Agent

## 📋 概述

**Personas** 是 AI 角色库的高级功能,提供人格导向的全流程技术指导体验。

与传统的职责型 Agent 不同,Persona 模拟真实技术大师的思维方式和交流风格,为用户提供一致的、导师式的技术指导。

---

## 🎯 核心概念

### 职责型 Agent vs 人格型 Agent

| 维度           | 职责型 Agent (Role-based)   | 人格型 Agent (Persona-based)     |
| -------------- | --------------------------- | -------------------------------- |
| **设计理念**   | 单一职责原则 (What to do)   | 人格导向 + 多职责 (How to think) |
| **特征**       | 专业、精准、高效            | 导师式、全流程、一致思维         |
| **示例**       | code_reviewer, api_designer | linus_torvalds, martin_fowler    |
| **Token 消耗** | ~1,200 tokens               | ~2,500 tokens                    |
| **使用场景**   | 明确的单一任务              | 需要全流程指导、复杂技术决策     |

### 为什么需要人格型 Agent?

| 用户需求                   | 职责型解决方案      | 人格型解决方案                |
| -------------------------- | ------------------- | ----------------------------- |
| 方案讨论+代码审查+Bug 分析 | 切换 3 个 Agent     | 1 个 Linus 人格,全流程参与 ✅ |
| 保持一致的技术视角         | 每个 Agent 独立视角 | 统一的人格思维方式 ✅         |
| 自然的导师式指导           | 专业但较机械        | 像真实导师对话 ✅             |

## 💡 使用场景

### 何时使用 Persona?

✅ **推荐使用 Persona**:

- 需要全流程技术指导(从架构 → 设计 → 代码 → 测试)
- 复杂技术决策需要深度讨论
- 希望保持一致的技术视角
- 追求自然的导师式交流体验

❌ **推荐使用职责型 Agent**:

- 明确的单一任务(如代码审查、API 设计)
- 追求效率和专业度
- Token 消耗敏感

### 典型使用场景

**场景 1: 全流程技术指导**

```
用户: "@角色:Linus 我想设计一个分布式缓存系统"
Linus: "别搞那些花里胡哨的,先说需求..."
[从架构→数据→接口→代码,全程同一视角]
```

**场景 2: 复杂技术决策**

```
用户: "@角色:Martin 这个架构该不该重构?"
Martin: "让我们先看看代码异味..."
[渐进式分析,给出重构建议]
```

**场景 3: 代码质量提升**

```
用户: "@角色:Uncle Bob 审查这段代码"
Uncle Bob: "违反了单一职责原则..."
[严格的质量标准,教育式指导]
```

---

## 🔄 Persona + Role 混合使用

**最佳实践**: Persona 负责方向把控,Role 负责具体执行

```
用户: "@角色:Linus 我要设计API"
Linus: "说需求,别搞RESTful教条..."
[讨论方向]
Linus: "方向对了,细节让API设计师来"
AI: [切换到 api_designer,完成详细设计]
```

**优势**:

- Persona 提供一致的技术视角
- Role 提供专业的执行能力
- 兼顾体验和效率

## 📊 Token 消耗与 ROI

| 项目           | Token 消耗 | 使用场景   | ROI 评估  |
| -------------- | ---------- | ---------- | --------- |
| 职责型 Role    | ~1,200     | 单一任务   | 高效率 ✅ |

## 🎯 调用方式

### 方式 1: 自然语言调用

## 📝 使用建议

1. **首次使用**: 建议先阅读具体 Persona 的文档,了解其思维方式和风格
2. **选择 Persona**: 根据技术栈和个人偏好选择合适的 Persona
3. **保持对话**: Persona 适合长对话,充分发挥其全流程指导能力
4. **灵活切换**: 必要时可以切换到职责型 Agent 完成具体任务
