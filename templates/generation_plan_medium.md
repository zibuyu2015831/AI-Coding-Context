## 🎯 第四阶段：AI 互审机制 `[MUST]`

### 互审流程

Medium 级别项目**必须执行 AI 互审**：

1. **生成初稿**: AI 生成者完成方案
2. **切换角色**: 使用 `agents/runtime/plan_reviewer.md` 角色
3. **执行审查**: 按审查清单检查
4. **评估置信度**: 给出 0-100 分的置信度
5. **优化完善**: 根据审查意见优化

### 审查清单

- [ ] 数据准确性（项目规模统计）
- [ ] 代码示例真实性
- [ ] 子文档规划合理性
- [ ] 架构识别准确性
- [ ] 脱敏处理完整性

### 置信度评估

**目标置信度**: ≥ 80 分

| 置信度  | 评级         | 后续动作         |
| ------- | ------------ | ---------------- |
| 90-100% | 非常确信     | 提交人工审核     |
| 80-89%  | 整体良好     | 提交人工审核     |
| 70-79%  | 可用但有问题 | **必须人工审核** |
| < 70%   | 存在重大问题 | **必须人工审核** |

### 审查报告格式

```markdown
## AI 互审报告

**审查者角色**: Plan Reviewer
**审查日期**: [YYYY-MM-DD]
**置信度**: [X]%

### 发现的问题

1. [问题描述] - 优先级: [P0/P1/P2]
2. ...

### 优化建议

1. [建议]
2. ...

### 总体评价

[评价]
```

## 🔄 持续维护规划

### 维护触发条件

| 优先级 | 触发条件                                    | 示例         | 响应时间 |
| ------ | ------------------------------------------- | ------------ | -------- |
| **P0** | 核心架构变更、主框架大版本升级、错误率 >30% | REST→tRPC    | 立即     |
| **P1** | 新增核心模块、代码变更>30%、错误率 15-30%   | 新增支付模块 | 2 周内   |
| **P2** | 辅助功能、代码变更 10-30%、距上次 >3 月     | 工具函数优化 | 1 月内   |

## ✅ 填写指南

### 如何填写本方案

1. **项目基础分析** (必填)

   - 完整填写所有统计数据
   - 提供验证命令
   - 识别 4-10 个业务模块

2. **核心代码模式提取** (必填)

   - 至少提取 3-4 种核心模式
   - 必须来自真实代码

3. **子文档规划** (必填)

   - 至少规划 3 个必需子文档
   - 明确每个文档的内容来源

4. **AI 互审** (必须执行)

   - 按照互审流程执行
   - 置信度必须 ≥ 80%

5. **维护规划** (必填)
   - 根据项目实际情况调整

### 常见问题

**Q: Medium 项目必须执行 AI 互审吗？**
A: 是的，Medium 及以上级别必须执行 AI 互审，以提高方案质量。

**Q: 置信度低于 80% 怎么办？**
A: 必须人工审核。AI 应详细说明不确定的部分，请求用户提供更多信息。

**Q: 子文档数量如何确定？**
A: Medium 项目建议 3-5 个子文档。具体根据项目模块数量和复杂度调整。
