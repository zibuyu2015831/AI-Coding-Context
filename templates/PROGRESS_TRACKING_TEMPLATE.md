## 🎯 批次执行建议

### 小型项目 (< 5K 行)

```
第1次会话: 阶段0 + 阶段1
第2次会话: 阶段2 (全部子文档)
第3次会话: 阶段3 + 阶段4
```

**总计**: 3 次会话，约 4-6 小时

---

### 中型项目 (5K-20K 行)

```
第1次会话: 阶段0
第2次会话: 阶段1
第3次会话: 阶段2-第一批
第4次会话: 阶段2-第二批
第5次会话: 阶段2-第三批 + 阶段3
第6次会话: 阶段4
```

**总计**: 5-6 次会话，约 8-12 小时

---

### 大型项目 (20K-50K 行)

```
第1次会话: 阶段0
第2次会话: 阶段1 (仅核心章节)
第3次会话: 阶段1 (补充章节)
第4次会话: 阶段2-第一批 (3个核心文档中的1个)
第5次会话: 阶段2-第一批 (剩余2个)
第6-10次会话: 阶段2-其他批次 (每次1-2个文档)
第11次会话: 阶段3
第12次会话: 阶段4
```

**总计**: 10-12 次会话，约 20-30 小时，分 2-3 天

---

### 超大型项目 (> 50K 行)

**建议策略**：按**模块**逐个完成

```
模块A:
  第1-2次会话: 阶段0 + 阶段1 (仅模块A)
  第3-5次会话: 阶段2 (模块A的子文档)
  第6次会话: 阶段4 (验证模块A)

模块B:
  [重复上述流程]

最后:
  第N次会话: 整合所有模块文档
  第N+1次会话: 全局验证优化
```

**总计**: 根据模块数定，可能需要 1-2 周

## ⚠️ 分批执行注意事项

### 1. AI 上下文管理

**问题**: AI 的上下文窗口有限

**解决**:

- 每批开始时，让 AI 读取：
  - 主文档（如已生成）
  - GENERATION_PLAN（方案文档）
  - PROJECT_ANALYSIS_REPORT（问题报告）
- 每批结束时，让 AI 总结本批产出

### 2. 进度保存

**每个批次结束后**:

```markdown
## 本批次总结

- 完成文档: [列表]
- 遇到的问题: [记录]
- 待确认事项: [列表]
- 下批次计划: [说明]
```

**保存位置**: `dev_docs/_analysis/progress.md`

### 3. 一致性维护

**跨批次一致性检查**:

- [ ] 术语使用一致
- [ ] 代码示例风格一致
- [ ] 引用路径正确
- [ ] 无矛盾说明

### 4. 中断恢复

**如果中途中断**:

1. 查看本文档，确认完成度
2. 从未完成的批次继续
3. 让 AI 读取已完成的文档
4. 继续执行
