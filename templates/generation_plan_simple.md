## 📚 子文档规划（简化版）

### 必需子文档清单

对于 Simple 级别项目，**简化子文档结构**：

- [ ] `architecture_overview.md` - 架构总览（简化版）
  - **内容来源**: 项目结构、主要流程
  - **预计行数**: 150-200 行
  - **关键章节**:
    - 项目概述
    - 技术栈
    - 核心流程图（Mermaid）
    - 主要模块说明

### 可选子文档

根据项目特点，可选择性生成：

- [ ] `api_layer.md` - API 文档（如果有多个 API）
- [ ] `deployment.md` - 部署文档（如果部署较复杂）

**说明**: Simple 级别项目通常不需要多个子文档，主文档即可覆盖大部分内容。

## 🔄 维护规划

### 触发条件

| 优先级 | 触发条件                 | 示例         | 响应时间 |
| ------ | ------------------------ | ------------ | -------- |
| **P0** | 核心架构变更、主框架升级 | 框架版本升级 | 立即     |
| **P1** | 新增模块、代码变更>30%   | 新增功能模块 | 2 周内   |

### 健康度检查

**检查频率**: 每季度

**检查内容**:

- [ ] 代码示例是否仍可运行
- [ ] 文件路径是否准确
- [ ] 依赖版本是否需要更新

### 维护策略

- **主文档**: 代码变更时及时更新
- **子文档**: 按需更新，保持与代码同步
- **问题记录**: 记录到 knowledge/troubleshooting/

## ✅ 填写指南

### 如何填写本方案

1. **项目基础分析**

   - 完整填写所有统计数据
   - 提供验证命令证明数据准确性

2. **核心代码模式提取**

   - 选择 1-2 个最重要的代码模式
   - 必须来自真实代码，注明文件路径

3. **子文档规划**

   - 评估是否需要 architecture_overview.md
   - 如果项目非常简单，可只生成主文档

4. **维护规划**
   - 根据项目实际情况调整触发条件

### 常见问题

**Q: Simple 项目是否需要 AI 互审？**
A: 不需要。Simple 级别项目复杂度低，人工审核即可。

**Q: 是否需要生成子文档？**
A: 可选。如果项目有明确的架构层次，建议生成 architecture_overview.md；如果项目很简单，只生成主文档即可。

**Q: 如何判断项目是 Simple 还是 Medium？**
A: 主要看文件数（10-100 为 Simple）和模块数（2-3 个为 Simple）。如有疑问，参考智能选择算法的评分。
