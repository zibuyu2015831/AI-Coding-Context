# 文档健康度报告模板

> **版本**: v2.3  
> **创建日期**: 2025-11-28  
> **用途**: 标准化健康度检查报告格式

---

## 📋 模板说明

本文档提供三种健康度报告模板，对应三种检查模式：

1. **简化版**: 用于模式 1（快速扫描）
2. **标准版**: 用于模式 2（标准检查）
3. **详细版**: 用于模式 3（深度分析）

---

## 📊 简化版报告模板

**适用**: 模式 1 - 快速扫描

```markdown
📊 文档快速扫描结果

- 文档生成日期: YYYY-MM-DD（XX 天前）
- 文档记录文件: XXX 个
- 当前代码文件: XXX 个
- 差异: ±XX 个文件（±X.X%）

💡 初步评估: [状态描述]

📋 建议操作:
A. 执行标准健康度检查（推荐）
B. 执行深度分析
C. 直接增量更新
D. 重新生成文档
E. 保持现有文档

请选择: A / B / C / D / E
```

**使用说明**:

- 替换所有`XXX`和`XX`为实际数值
- `[状态描述]`根据差异百分比填写：
  - <5%: "文档基本准确"
  - 5-15%: "文档可能部分过时"
  - > 15%: "文档可能明显过时"

**使用说明**:

1. **健康度等级对应**:

   - 90-100 分: 🟢 优秀 - 无需更新
   - 70-89 分: 🟡 良好 - 建议选择性更新
   - 50-69 分: 🟠 一般 - 建议增量更新
   - 30-49 分: 🔴 较差 - 强烈建议全量更新
   - <30 分: ⛔ 极差 - 必须重新生成

2. **风险区域分类**:

   - 🔴 高风险: 核心文件变更、架构调整
   - 🟡 中风险: 业务模块变更、新增功能
   - 🟢 低风险: 工具类、样式文件变更

3. **推荐方案对应**:
   - 90-100 分: 无需更新
   - 70-89 分: 增量更新（选择性）
   - 50-69 分: 增量更新
   - 30-49 分: 全量更新
   - <30 分: 重新生成

## 🔧 模板使用指南

### 选择合适的模板

| 场景         | 推荐模板 | 理由             |
| ------------ | -------- | ---------------- |
| 快速了解状态 | 简化版   | 1 分钟，最低成本 |
| 常规评估     | 标准版   | 平衡准确度和成本 |
| 长期未更新   | 详细版   | 最全面的分析     |
| 重大变更后   | 详细版   | 需要精确评估     |
| 定期检查     | 标准版   | 适合常规维护     |

### 填写技巧

1. **保持一致性**: 同一报告中的术语和格式要统一
2. **数据可验证**: 提供验证命令或数据来源
3. **建议可执行**: 给出的建议要具体可行
4. **优先级明确**: 清楚标注哪些是必须、建议、可选

### 常见错误

❌ **错误示例**:

- 健康度: "还行"（应该是具体分数）
- 建议: "更新一下文档"（应该具体到哪些文档）
- 工作量: "不多"（应该是具体小时数）

✅ **正确示例**:

- 健康度: 65 分（一般）
- 建议: 更新 architecture_overview.md 和 authentication.md
- 工作量: 2-3 小时
