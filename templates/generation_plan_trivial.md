## 📚 文档规划

### Trivial 级别项目文档策略

对于超简单项目，**不创建复杂的文档体系**，仅生成：

1. **主文档** `AI_Coding_Context.md`（根目录）

   - **包含章节**:
     - 项目概述
     - 快速使用
     - 核心代码说明
     - 依赖说明
     - 常见问题
   - **预计行数**: 100-200 行

2. **plans/ 目录**（可选）

   - 用于记录后续改进计划

3. **knowledge/ 目录**（可选）
   - 用于记录使用技巧

**不生成**:

- ❌ 不生成子文档（项目太简单）
- ❌ 不需要架构文档
- ❌ 不需要 API 文档

## ✅ 填写指南

### 如何填写本方案

1. **项目基础分析**

   - 列出主要文件和功能
   - 统计基本规模（文件数、代码行数）

2. **核心代码模式**

   - 可选章节，如果代码很简单可跳过
   - 如填写，选择最关键的代码片段

3. **文档规划**

   - 不需要修改，按标准执行即可
   - 只生成主文档，不生成子文档

4. **维护规划**
   - 按实际需要调整触发条件

### 常见问题

**Q: Trivial 项目是否需要 AI_RULES.md？**
A: 可选。如果项目非常简单（如单文件脚本），可以不生成。

**Q: 是否需要创建 plans/ 和 knowledge/ 目录？**
A: 可选。如果预期项目会持续迭代，建议创建；否则可跳过。

**Q: 主文档应该包含哪些内容？**
A: 项目概述、快速使用、核心代码说明、依赖说明、常见问题。保持简洁，避免过度文档化。
