## 📝 核心问题

**何时应该更新 AI 文档?**

当项目代码发生变化后,并非所有变更都需要更新文档。本规范定义了明确的触发条件。

---

## 🎯 更新触发分级

### P0: 必须更新 (影响 AI 理解和开发效率)

**立即更新文档的情况**:

1. ✅ **新增核心功能模块**

   - 示例: 新增支付模块、用户系统等
   - 影响: AI 需要理解新模块的职责和接口

2. ✅ **架构重大变更**

   - 示例: 引入新的设计模式(MVC→MVVM)
   - 影响: 整体架构理解变化

3. ✅ **数据库 schema 变更**

   - 示例: 新增表、修改字段、改变关系
   - 影响: 数据模型理解变化

4. ✅ **API 接口重大变更**

   - 示例: 新增/删除端点、参数变化、响应格式变化
   - 影响: API 调用方式变化

5. ✅ **开发规范变更**
   - 示例: 状态管理方案改变(Vuex→Pinia)
   - 影响: 编码方式变化

### P1: 建议更新 (有助于保持文档准确性)

**建议更新文档的情况**:

1. ✅ **修复影响理解的重大 Bug**

   - 示例: 修复了架构设计缺陷
   - 影响: 对系统理解更准确

2. ✅ **新增重要配置项**

   - 示例: 新增环境变量、配置参数
   - 影响: 部署和配置方式变化

3. ✅ **第三方依赖大版本升级**

   - 示例: Vue 2→Vue 3, React 16→React 18
   - 影响: API 使用方式可能变化

4. ✅ **新增重要的最佳实践**
   - 示例: 新的错误处理模式
   - 影响: 代码质量提升

### P2: 可选更新 (不影响理解但可记录)

**可选更新的情况**:

- 小功能优化
- 代码重构(无功能变更)
- 文档错别字修正
- 性能优化(不改变接口)

---

## 🔄 更新方式

### 小范围更新

**适用场景**: P1 级别的变更,影响 1-2 个子文档

**操作步骤**:

1. 仅更新相关的子文档
2. 在子文档开头注明"最后更新"时间
3. 在主文档的更新记录中添加一条

**示例**:

```markdown
# API 层文档

> **最后更新**: 2025-11-27  
> **更新内容**: 新增支付接口说明

...
```

### 大范围更新

**适用场景**: P0 级别的变更,影响多个文档或架构

**操作步骤**:

1. 重新运行框架生成流程
2. AI 会检测已有文档
3. 增量更新变更的部分
4. 生成更新报告

**命令**:

```
告诉AI: "项目有重大更新,请更新AI文档"
并提供变更说明
```

## 📐 AI_RULES 中的触发规则

在生成的`dev_docs/rules/combined/AI_RULES.md`中,应包含以下规则:

```markdown
## 📝 文档更新触发器

当你完成以下类型的工作后,应提醒用户更新 AI 文档:

**立即更新**:

- 新增核心模块或功能
- 修改数据库 schema
- 修改 API 接口

**建议更新**:

- 修改开发规范
- 重大重构完成

**更新命令**:
请用户将最新的 AI_Coding_Context.md 发送给你,
并告诉你"文档需要更新"。
你将分析变更,增量更新相关文档。
```

## 💡 最佳实践

### 定期 review

**建议频率**:

- 小项目: 每月 review 一次
- 中大项目: 每 2 周 review 一次
- 重大迭代后: 立即 review

### 更新记录

在`AI_Coding_Context.md`中维护更新记录:

```markdown
## 📝 更新记录

| 日期       | 更新内容           | 影响范围                               | 更新人 |
| ---------- | ------------------ | -------------------------------------- | ------ |
| 2025-11-27 | 新增支付模块       | api_layer.md, architecture_overview.md | 张三   |
| 2025-11-20 | 数据库 schema 变更 | database_schema.md                     | 李四   |
```

### 团队协作

**多人项目**:

1. 指定文档维护负责人
2. 重大变更时通知负责人
3. 定期 review 会议讨论文档更新

## ❓ 常见问题

**Q: 如何判断是 P0 还是 P1?**  
A: 问自己:"如果 AI 不知道这个变更,会导致什么?"

- 会生成错误代码 → P0
- 会生成过时但不影响功能的代码 → P1
- 几乎无影响 → P2

**Q: 增量更新是什么意思?**  
A: AI 会:

1. 读取现有文档
2. 识别变更部分
3. 只更新变更的章节
4. 保留未变更的内容

**Q: 更新文档需要多久?**  
A:

- 小范围更新: 5-10 分钟
- 大范围更新: 20-30 分钟
- 完整重新生成: 与首次生成时间相同
