# 创建自定义 Agent 工作流

## 📋 工作流概述

本工作流指导 AI 如何辅助用户创建项目专属的自定义 Agent。

**触发方式**: `@workflow:创建自定义Agent`

**目标**: 通过 5 个 Phase 的结构化流程,生成高质量的自定义 Agent 文档

---

## 🔄 Phase 1: 需求收集

### AI 执行步骤

通过 3-5 轮提问,收集用户需求:

**必问问题**:

1. **核心职责**: "这个自定义 Agent 的核心职责是什么?"
2. **技术栈/场景**: "它主要应用在哪些技术栈或场景?"
3. **输入输出**: "主要的输入和输出是什么?"

**可选问题**:

4. **协作角色**: "它会与哪些角色协作?"
5. **项目特定规范**: "有没有项目特定的编码规范或业务规则?"

### 输出

整理后的需求摘要,包含:

- 角色英文名(用于 ID)
- 角色中文名
- 核心职责描述
- 技术栈
- 主要输入输出

---

## 🔍 Phase 2: 深度分析 (AI 自主完成)

### 2.1 查重检查

**目的**: 避免创建重复的角色

**步骤**:

1. 搜索`agents/`目录下所有角色的元数据
2. 语义相似度分析(基于职责描述)
3. 如发现相似角色(相似度>70%),询问用户:

   ```
   发现已有类似角色:
   - [角色名称] - [职责描述]

   是否仍要创建新角色? (y/n)
   ```

### 2.2 必要性评估

**判断标准**:

- ✅ 框架角色无法满足需求
- ✅ 涉及项目特定技术栈或业务规则
- ❌ 可通过调整现有角色参数解决

**输出**: 必要性评估结论

### 2.3 扩展点分析

**目的**: 识别自定义 Agent 的独特功能

**步骤**:

1. 对比框架角色的功能
2. 头脑风暴自定义 Agent 的特有功能
3. 列出差异点清单

### 2.4 边界分析

**目的**: 明确职责范围,避免重叠

**输出**:

- 该角色负责什么
- 该角色不负责什么
- 与现有角色的职责划分

### 2.5 依赖识别

**目的**: 自动识别协作关系

**步骤**:

1. 分析输入来源 → 识别上游角色
2. 分析输出去向 → 识别下游角色
3. 建议依赖关系

---

## 📝 Phase 3: 生成草稿

### AI 执行步骤

基于`agents/custom/_template.md`,生成完整文档:

**3.1 填充元数据**

```markdown
<!-- AGENT_META_START -->

ID: custom.{角色英文名}
名称: {角色中文名}
类型: development # 或 language_specific
版本: v1.0
创建: {当前日期}
更新: {当前日期}
来源: user
改造状态: 已通用化
语言支持: {通用/特定语言}
标签: [{标签 1}, {标签 2}, {标签 3}]
依赖: [{依赖角色 ID 列表}]
被依赖: []
可编辑性: editable

<!-- AGENT_META_END -->
```

**3.2 生成角色概述**

基于需求摘要,填充:

- 职责(一句话)
- 适用场景(2-3 个)
- 专长领域(3-5 个)
- 协作角色

**3.3 编写 System Prompt**

- 身份定义: "你是一位经验丰富的{专业领域}专家..."
- 行为准则: ✅ 你应该 / ❌ 你不应该
- 输出规范: 格式要求和质量标准

**3.4 定义输入输出要求**

- 输入要求: 列举 3-5 项具体输入
- 输出要求: 列举 2-3 项具体输出

**3.5 创建快速示例**

- 典型输入示例
- 典型输出示例
- 关键点说明

**3.6 列出协作角色**

基于 Phase 2 的依赖识别结果

**3.7 定义评估标准**

至少包含 3 个维度,每个维度 2-3 个检查项

---

## 🔄 Phase 4: 迭代优化

### AI 执行步骤

1. **展示草稿**: 完整展示生成的文档
2. **询问反馈**: "请审查以上文档,是否需要修改?"
3. **根据反馈调整**:
   - 修改不准确的描述
   - 补充遗漏的内容
   - 调整示例
4. **迭代限制**: 最多 3 轮迭代

### 用户可能的反馈

- "职责描述不够准确"
- "需要补充 XX 场景"
- "示例不够清晰"
- "评估标准需要调整"

---

## ✅ Phase 5: 保存和注册

### AI 执行步骤

**5.1 保存文档**

```
保存到: agents/custom/{角色英文名}.md
```

**5.2 更新索引**

在`agents/custom/README.md`的"自定义 Agent 索引"部分添加:

```markdown
### {角色中文名}

**ID**: `custom.{角色英文名}`  
**职责**: {一句话描述}  
**文档**: [{角色英文名}.md](./{角色英文名}.md)
```

**5.3 生成使用示例**

提示用户如何使用:

```
✅ 自定义Agent创建成功!

📄 文档位置: agents/custom/{角色英文名}.md

🎯 使用方式:
1. IDE集成: 复制文档内容到AI IDE的agent配置
2. 自然语言: "@角色:{角色中文名} {任务描述}"

💡 建议: 先测试该角色是否符合预期,必要时可直接编辑文档调整
```

## 🔍 质量检查机制

### 自动检查清单

在 Phase 3 生成草稿后,AI 自动执行:

**格式检查**:

- [ ] 元数据区完整(AGENT_META_START/END)
- [ ] ID 格式正确(`custom.{name}`)
- [ ] 必需字段无遗漏(13 个字段)

**内容检查**:

- [ ] 角色概述清晰
- [ ] 输入输出要求明确
- [ ] 至少有 1 个快速示例
- [ ] 评估标准不少于 3 条

**唯一性检查**:

- [ ] ID 不与现有角色冲突
- [ ] 职责无显著重叠(Phase 2 已检查)

### 检查失败处理

如检查失败,AI 自动修复后重新检查,最多重试 2 次
